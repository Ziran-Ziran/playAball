## 已确定

- 名称：玩个球；内部仓库名：playAball。
- 三人开发，其中两位程序；约 90% 的开发由 Agent 协助。
- 平台：PC；新肉鸽 Demo 采用 2D 正俯视平面、零环境重力（用户于 2026-10-30 确认）。旧实验原型保留横版侧视与向下重力。
- 技术：Godot 4.7.1 stable 标准版、GDScript、内置 Godot Physics 2D、Compatibility 渲染。
- 新 Demo 核心循环：观察 → 在游戏窗口全屏空白处拉动 → 运动中也可冲量发射 → 主球撞击供能、小兵受撞散射接力（初始不跟随，升级后可归队） → 击杀门槛奖励（三选一/升级后四选一） → 清波/首领与结算。详见 [Demo 方案](ideas/COLLISION_ROGUELITE_DEMO.md)。
- 旧实验循环保留：观察 → 在停稳的球上向后拖拽 → 松开发射 → 碰撞/机关 → 进入目标或重试。
- 核心体验：可预测的物理碰撞，辅以强度相关的闪光、粒子、轻微镜头震动和音效。

## 当前建设与旧原型验收

新 Demo 先迁移并验收 P0～P2，之后通过真实玩家试玩再推进 P3～P5。P0～P2 已保存为本地提交528e8e6；用户接受后，本地继续实现三敌人、五波/十五项击杀发育池、首领/胜负和肥鱼白饭。新入口run.tscn，旧三靶场保留，实际通关时长/难度和主题手感待玩家验收；任务状态见 STATUS。新场景逐刚体禁用环境重力，不能改坏旧原型。默认主题为肥鱼，白饭局部吸力仍作用于二维平面。

一个可运行的实验关：地面、墙、障碍、球、目标、力度/方向可视化、胜利、重置、出界保护；三种互斥的实验机关模式（加速、粘滞、反向重力）。可多次击球，不限杆数，记录本轮击球次数。机关服务于手感测试，不代表最终关卡设计。

先使用代码绘制几何占位美术和合成碰撞音，避免外部素材和许可证依赖。碰撞闪光先使用绘制发光环模拟；真实灯光与最终美术、音效后续单独迭代。

## 旧实验原型的方案比较与选择

1. **单关卡实验原型（采用）**：先验证发射与碰撞，结构简单，适合学习。
2. 多关卡框架：需要关卡切换、存档、关卡设计，当前验证成本较高。
3. 完整美术竖切片：表现更完整，但会在物理参数未稳定前投入较多素材工作。

## 模块边界

`ball` 负责刚体、发射和接触事件；`mechanism` 负责 Area2D 区域；`impact_feedback` 只消费碰撞事件；`main` 组织关卡、输入和 UI。使用信号解耦表现与物理。参数使用 `@export`；场景使用 `.tscn`，可在编辑器中调布局。

以上是旧实验模块；新玩法使用独立的 `scenes/roguelite/` 与 `scripts/roguelite/`，职责及迁移范围见 [迁移计划](plans/003-collision-roguelite.md)，不替换旧模块。

新版的最小表现接口已从敌人 actor 和生命面板开始落地：`DemoEnemy` 提供只读快照与真实表现事件，`DemoEnemyView` 只绘制；`DemoHealthView` 从正式HUD拆出，HUD只委托绑定。按钮仍只发请求，伤害、奖励、购买和阶段切换由玩法组件校验。未迁移的玩家、伙伴、首领、音频和其余混合文件继续按当前单写者运行，不假装已经全部拆分。
