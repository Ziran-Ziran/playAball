# 项目概况

## 已确定

- 名称：玩个球；内部仓库名：playAball。
- 三人开发，其中两位程序；约 90% 的开发由 Agent 协助。
- 平台：PC；视角：2D 横版侧视（类似森林冰火人的画面方向），有向下重力。
- 技术：Godot 4.7.1 stable 标准版、GDScript、内置 Godot Physics 2D、Compatibility 渲染。
- 核心循环：观察 → 在停稳的球上向后拖拽 → 松开发射 → 碰撞/机关 → 进入目标或重试。
- 核心体验：可预测的物理碰撞，辅以强度相关的闪光、粒子、轻微镜头震动和音效。

## 第一版验收

一个可运行的实验关：地面、墙、障碍、球、目标、力度/方向可视化、胜利、重置、出界保护；三种互斥的实验机关模式（加速、粘滞、反向重力）。可多次击球，不限杆数，记录本轮击球次数。机关服务于手感测试，不代表最终关卡设计。

先使用代码绘制几何占位美术和合成碰撞音，避免外部素材和许可证依赖。碰撞闪光先使用绘制发光环模拟；真实灯光与最终美术、音效后续单独迭代。

## 方案比较与选择

1. **单关卡实验原型（采用）**：先验证发射与碰撞，结构简单，适合学习。
2. 多关卡框架：需要关卡切换、存档、关卡设计，当前验证成本较高。
3. 完整美术竖切片：表现更完整，但会在物理参数未稳定前投入较多素材工作。

## 模块边界

`ball` 负责刚体、发射和接触事件；`mechanism` 负责 Area2D 区域；`impact_feedback` 只消费碰撞事件；`main` 组织关卡、输入和 UI。使用信号解耦表现与物理。参数使用 `@export`；场景使用 `.tscn`，可在编辑器中调布局。

## 本轮不做

联网、关卡编辑器、存档、正式发行、商业素材采购、完整关卡组、复杂插件体系。后续方向由团队试玩后决定。

## 协作与决策

main 保持能运行；一个任务一条分支一个 PR。程序 A/程序 B/策划美术是职责建议，由团队自行分配。涉及玩法的大改先更新本文并记录原因。未经团队明确决定，不引入新语言、引擎升级或外部运行依赖。
