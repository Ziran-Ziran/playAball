## 从时间到显示

浏览器读取同一张v2卡框 → 放入三张/四张布局 → 各张按100毫秒错开 → 420毫秒内从透明、下移24像素、98.5%比例逐渐落位 → 减速停稳，不回弹。三张约620毫秒、四张约720毫秒落稳。

`setPreviewTime(milliseconds)`只修改显示层。上移、透明度和轻微缩放采用`1-(1-t)^3`减速曲线，没有超调。这里的24像素是浏览器小样尺寸，不是玩法世界位移。叠加的SVG圆角轮廓上有一段短亮线，以2400毫秒一圈缓慢流动，宽度与亮度保持克制；PNG本身不被重画。选择减少动态效果的系统偏好时关闭位移/缩放和沿边流光，仅淡入。

当前2400毫秒自动循环只为方便评价，真实游戏每次有效打开选卡只播放一次，不应反复弹出。预览标题由浏览器显示，源PNG中没有文字。

## 如何修改

双击HTML查看。调整100可改逐张间隔，420可改每张入场时长，24可改位移，`.985`与`.015`控制起始比例与收敛。流光轮廓的`pathLength=1000`用于统一路径长度，`stroke-dasharray='45 955'`控制亮段占比，0.55控制透明度。换素材时需复核轮廓坐标，不能照搬到任意尺寸。改动时同步本教程；图案与文案单独设计，保持PNG与动态文字分离。

本批尚无Godot场景或检查器参数。后续独立表现组件可将间隔、时长、位移、轻弹、减少动态开关暴露为`@export`。A交素材和表现参数，B负责接真实奖励报价、等级、上限、说明与选择请求。显示文字应按真实卡片内容重新排版并检查长中文，不能以空白卡框测试证明文案可读。

## 常见错误

- 把整张卡框拉伸到不同纵横比：会把切角和边线拉变形，先保持比例，正式组件再设计边框缩放方式。
- 在生成图里烘焙说明和等级：会妨碍实时更新，文字由游戏读取状态后显示。
- 把展示循环直接用于正式选卡：会不断弹出，正式每次打开只触发一次。
- 靠动画回调直接发奖励：表现仅显示并提交选择请求，规则由B校验。
