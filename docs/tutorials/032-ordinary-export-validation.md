# 普通包导出与内嵌资源验证

普通包从肥鱼主菜单开始，开局零伙伴。开发者在源工程仍可打开实验室和调参场景；默认导出过滤这些资源，不能把调参说明塞进普通包让试玩者按不存在的F1。

## 使用方法

在项目根目录运行：

```powershell
./tools/export_windows.ps1 -GodotExe <本机Godot4.7.1实际路径> -BuildName <新的唯一名称>
```

脚本拒绝覆盖已有构建。它只在项目忽略的`.local/export-随机ID`复制运行资源、写暂存配置、导入和导出，不写回原project.godot。产物在`builds/<名称>/PlayABall.exe`及同名zip。修改游戏后必须新建名称，不能把旧EXE说成新代码结果。

`-LiveTuning`仍是显式开发包开关；本轮交付使用默认普通模式。普通模式选择OVERNIGHT_README/FEEDBACK，而开发模式保留旧策划说明。

## 过滤与指纹

默认暂存export_presets.cfg排除tuning/lab/evaluation/balance候选、音频预览入口、旧横版原型入口和生图来源JSON。实际运行仍需动态加载15项升级、四张地图、白饭与所有美术资源，因此保留all_resources加明确排除，避免只导出静态场景依赖后漏掉动态资源。

`runtime_source_sha256`是暂存输入加导出过滤规则的指纹，不是EXE文件哈希；`exe_sha256`才是交付EXE哈希。前者包含被过滤前的源输入，修改开发脚本也可能改变。实际包内容由package_manifest.json逐项列出；不要根据暂存目录里仍有源文件就误认为已打进包。

## 为什么不能直接给发布EXE传外部测试脚本

Godot4.7标准发布模板禁用路径覆盖；`--script`这类参数只在编辑器或显式支持覆盖的模板可用，未知参数会被静默忽略。[官方命令行说明](https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html)。本轮首次直接调用发布EXE的外部探针没有运行，已停止这一任务自有进程，保留失败日志；没有开启不安全的路径覆盖或把诊断入口塞入游戏。

采用同版本编辑器引擎的`--main-pack <导出EXE>`读取真实内嵌包，再执行外部`tools/package_probe.gd`。`--path`和工作目录必须明确指向构建目录，否则被排除资源可能回退到源工程磁盘文件，产生“包内仍有开发场景”的假阳性。第二次诊断确认manifest中没有这些文件，隔离路径后检查通过。导出器设40秒探针上限，失败不生成交付zip。

探针枚举实际包目录、检查入口与排除列表，然后实例化包内菜单，通过正式按钮请求进入Game；检查零伙伴、全部动态升级和地图/位图；向Input发送鼠标事件，确认正式发射；检查暂停、真实生命死亡、结算重开与胜利界面回菜单。胜利入口是明确的状态夹具，不冒充自然首领通关。它验证实际导出资源在同版引擎中的逻辑，不能冒充对发布模板原生窗口输入的验证。

## 原生发布版的边界

普通发布EXE另做Movie Maker限帧启动，实际使用RTX5070Ti Laptop的Compatibility渲染，保存主菜单原始录像和截图。它证明发布模板能启动和显示素材，不等于鼠标操作通过。CLI请求1024时Movie Maker仍输出逻辑1280×720；小窗口尺寸证据使用此前真正的1024窗口运行截图。

本轮computer-use两次无法激活发布窗口，报`failed to activate captured window`且截图黑。按技能恢复规则停止原生输入，等待用户确认桌面可交互；没有改用另一套注入方法绕过。原生鼠标/键盘和真实人类完整局目前均未验收。

音频证据由`.local/overnight/record_audio_events.gd`调用真实AudioDirector，以SFX0.65/UI0.7录下10类事件及密集接触中受伤/奖励，保存事件/变体/分贝记录。Movie Maker的实际混音提取为audio-events.wav；18.4秒、双声道48k、峰值约-21.48dBFS、无削波，只是客观指标，不代表真人试听通过。本批没有以这些测量为由擅自改变音色。

## 如何定位失败

- 导入或导出失败：看对应`.local/export-ID/import|export.out/err`，保留目录和未完成产物。
- 探针失败：看package_probe.out/err及manifest.failures；先确认隔离路径，再查动态资源或过滤规则。不要去掉断言换取zip。
- 源工程正常但包中丢图：查.import配置和包内资源映射，不能只看原PNG存在。
- 不能激活原生窗口：报告实际错误、保留包和其他证据，等待可交互桌面，不能写成通过。

## 新鲜导入也必须检查图像内容

G5虽然资源存在检查通过，箱子仍因1254源PNG裁切坐标用在256导入纹理上而几乎消失。G6按实际纹理尺寸换算三个敌人材质区域；package_probe逐一检查区域在实际Texture2D边界内，并读取区域中心alpha>0.9。再通过真实EXE内嵌包渲染f4-package-g6-after状态截图，对照G5错误画面。资源存在、源码缓存正常与最终画面正确是三个不同结论。G6为当前推荐包，旧G5只作历史对照。

## 嵌套实例的源码/导出差异：G8修复

G7实包首领截图发现红刺缺失。实际加载四图后确认：map_02十字竖臂、map_03两条移动尖刺与传送端点覆盖、boss_map六段尖刺，在源码实例化正常，重新PackedScene.pack后丢失。此前资源存在、地图切换、安全入场与胜负探针通过，并没有覆盖这些实例内部内容；因此旧G1–G7包不能继续称完整四图交付。

修复保留原节点/参数，给修改了子节点的场景实例添加[editable path]：地图二CrossPivot，地图三MovingLeft/MovingRight/Portals，首领InnerRing及六个InnerSpikes实例。编辑器中对应“可编辑子节点”：需要改实例内部节点或其Shape时先开启，再保存场景；只修改实例根的position等不需要展开所有子节点。首领每段26×22独立Shape不能变回通用180×22。

maps回归新增真实重打包→实例化检查，先红后绿共64项。普通包探针现逐图核对0/4/2/6尖刺、长度/形状/掩码、十字物理/视觉竖臂及传送端点±500。G8另比较四图202个节点的路径、类型、变换、碰撞形状和关键机关参数，源码与真实PCK全部相同。它不是所有运行状态的穷尽证明。

独立实包接触夹具固定机关运动、保持真实Area与生命规则，通过物理状态接口把玩家放到接触点；地图三与首领分别5→4，未直接调用hurt。初始固定点被物理推离、没有接触的失败尝试保留，后用真实碰撞查询选择未占墙的接触点；未改游戏伤害或危险尺寸。小窗口G7/G8前后截图显示十字竖臂、移动刺、边侧传送门和六段内环红刺均恢复。该修复使导出包符合一直存在的源码规则，不能将前后包难度变化称为纯美术改进。

## 收尾有界稳定性覆盖

.local/overnight/final_stability.gd让源码与实际G12包各执行8组密集AI和16轮UI生命周期。四图按真实波次上限放置已通过安全查询/间距的混合敌人，预选合法构筑，真实发射与AI最多12秒、死亡即停；不注入生命、清敌或胜利。卡片请求放在普通_process调度，遵守入场disabled，避免已发现的物理flush间隙恢复暂停问题。

每轮释放后等待0.35秒再查节点/孤立节点，回到2/0基线；源码与包的关键结果和采样相同，没有出界恢复。效果上限每0.1秒采样，只能说明这些样本未越界，不是饱和/连续穷尽证明。首版脚本漏计数字段产生SCRIPT ERROR，虽退出0且failures为空也作废；只有v2干净日志计通过。原始g-stability-*与对照保留。

另有10AI的10.325秒实际GPU片段；1024/1280状态采样相同、最低3血。记录CPU0.53ms/GPU0.18ms均值与编码开销，不能称交互FPS或真人性能通过。1血状态仍以F批明确冻结夹具为证据。正式标题旧Demo字样改为玩个球 / playAball，只覆盖Game外壳，开发run入口仍保留旧实验标题。
