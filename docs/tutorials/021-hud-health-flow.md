# 021：生图血条怎样做逐格流光小样

## 目标与当前范围

用户批准的方向是“简洁而有力”、两角分布，以及红色血格上的逐格流光。用户反馈第一版“冲击感偏弱”，本版缩短扫光、提高亮峰并加逐格快速提亮回落，随后获得用户“这个挺不错了”的认可。本批仅交独立表现小样，认可不代表真实游戏已集成。负责人为A，当前检出`feat/feedback-planner-handoff`、HEAD `0de7d74`，提交树与本地记录的`origin/main=935b9b8`相同。未同步远端或切分支。

本批不改正式HUD、玩法脚本、生命数据、角色、物理、发射冷却环。没有commit/push/PR/merge授权，也没有给其他聊天或第三方发消息。

- `docs/art/hud_health_flow.gif`：浏览器按20毫秒间隔截取100张截图后编码，重复静止帧自动合并，总长2000毫秒、无限循环。深底便于观察透明资产。

## 从时间到画面

浏览器读取PNG → 计算本轮经过时间 → 移动一条窄亮带 → 用四个有血格的轮廓裁掉越界部分 → 与原贴图叠加。流光从左向右穿过，只有红格区域会变亮。空格、生命数字与外框固定，所以流光不表示回血、掉血或最大生命改变。

`setPreviewTime(milliseconds)`只改变叠加层的位置与透明度。每轮2000毫秒，前650毫秒扫描，其余1350毫秒隐藏；横向坐标从150走到490。渐变亮峰不透明度从第一版0.38增到0.86，两端为0；亮带变窄，保留红色底色。四格分别在110、235、360、485毫秒开始局部提亮：20毫秒升到0.46不透明度，再用120毫秒快速回落。没有全条白闪、画面震动或位置缩放。遮罩位置对应当前概念图，不能拿这套固定坐标直接连接任意生命上限。

## 怎样调与扩展

双击HTML即可看循环。当前是浏览器样板，Godot检查器中还没有对应参数。修改HTML中的2000可改循环周期，650控制扫光时长，渐变`stop-opacity`控制亮度；逐格提亮由`pulseStarts`、20/120毫秒包络与0.46峰值控制，调整扫光时长需同步格子触发时刻。修改时同时维护注释与本教程。

查看固定帧时，在地址末尾加`?capture=1`，再通过浏览器调用`window.setPreviewTime(260)`，得到第二格提亮和移动扫光；1500毫秒应完全隐藏。这只是演示控制接口，不是拟议的玩法API。

用户认可节奏后，A再交无字底板、独立红格/空格与图标。B负责把现有生命组件的当前/最大生命只读传给表现组件，按真实填充范围生成遮罩；最大生命改变、受伤、恢复、死亡与重开都要更新遮罩。可暴露周期、扫描时长、宽度、亮度、启用开关为检查器参数。被动血条必须鼠标穿透；暂停停止表现计时，重开清除旧动画进度。不能由亮带决定或反推生命。

## 常见错误

- 用整条白闪代替窄扫光：会盖掉红色并更抢注意力，先降低亮度和宽度。
- 让空格也亮：会误导为有血，遮罩只覆盖实际填充。
- 把概念图中的4/5、08当实时UI：这些是烘焙示例，正式资产应拆掉文字再由游戏显示。
- 为了接效果直接改`run_hud.gd`：该文件仍由B单写，先交独立素材与所需状态，不越过整文件交接。
