# 023：通用按钮和面板底板

## 当前反馈

用户已否定本教程对应的主菜单组合，认为缺乏创意。本文保留素材来源与复现事实；旧菜单不是获批方案。按钮和面板源图来自内置生图，整屏截图来自浏览器组合，两者不能混称。下一步先评完整生图菜单概念，再拆素材，见风格记录。

## 目标与边界

2026-11-01，用户认可简约科幻、流动卡框v2及其动态，要求生成其他UI。本批按剩余基础UI推进：通用无字按钮、通用无字面板，以及“开始游戏／设置／退出”排版小样。A负责美术，正式场景、菜单状态和运行接线仍由B整文件单写。当前检出基线仍`0de7d74`，与本地记录的`935b9b8`提交树相同，未切分支或同步远端。

这批不是完整菜单系统。具体成长卡面仍逐个设计；商店商品、事件、结算等具体版式还没做。没有修改玩法/物理/奖励、正式HUD或设置，没有commit/push/PR/merge或发消息授权。

## 素材与来源

- `docs/art/ui_button_base.png`：内置image_gen以已通过的`upgrade_card_frame_v2.png`为风格参考生成，2172×724 RGBA。单个横向无字按钮，外围透明，深色内面、细绿轮廓、柔和转角。
- `docs/art/ui_panel_base.png`：同一参考独立生成，1536×1024 RGBA，单张横向3:2无字面板，无内部隔断，供后续菜单组合。
- `docs/art/menu_preview.html`：浏览器组合上述素材，文字独立显示，默认主菜单，加`?states=1`查看平常/悬停/按下/禁用四态。
- `docs/art/menu_preview.png`：1280×720默认菜单截图，便于用户评价。

提示要点：沿用已认可卡框的轻薄细绿连续轮廓、柔和转角、暗灰绿安静内面；分别生成单个无字横按钮与单张无分隔横面板；外部透明，不添加机械装甲、粗切角、图标或烘焙文字。两张独立PNG由内置生图工具生成，浏览器只组合图像、显示文字和演示交互。没有下载/拆包素材。

## 输入 → 显示 → 演示反馈

浏览器读取PNG → 面板内布局标题与三个按钮 → 鼠标悬停或键盘焦点提亮图片 → 按下轻缩 → 点击只显示“美术小样，功能尚未接入”。不会启动或退出游戏，也不会改设置。

`.primary`将开始按钮亮度设为1.2，普通按钮0.82，悬停/焦点1.5；按下缩到0.985并将亮度降为1.04，禁用透明度0.38并减色。这些是可调整的演示值，四态不是四张另画贴图。按钮中文字由HTML显示，源图保持无字。

## 手动修改与未来Godot接入

双击HTML看默认菜单，加`?states=1`比较四态。修改标题/按钮文字不必重新生图；在CSS调整`.panel`宽度、`.action`尺寸和字号即可检查布局。源按钮有透明上下边距，小样以容器裁掉多余透明留白，不编辑源PNG；正式接入时复核可点击区域与可见轮廓一致。

当前没有Godot检查器组件；未来独立表现组件可将图片、字号、文本安全边距、四态调色和过渡时间暴露给检查器。正式使用建议保留纵横比，或专门制作可正确九宫格缩放的边框，不直接把大面板任意拉长。极端长中文和不同分辨率必须重新检查。

B接线需要区分`request_start`、`request_settings`、`request_exit`等请求，由状态机校验执行。正式暂停、商店和奖励面板延续各自报价/版本/余额校验；不能因复用底板就让按钮直接结算。被动面板区域穿透输入，实际按钮才独占；焦点可见、键盘可用。样板HTML不注册任何游戏输入。

## 实际验证与限制

沿用本会话核验设备LAPTOP-8GS4N5SG、Windows、Ziran及Godot4.7.1 stable标准版环境。浏览器1280×720默认菜单已查看，1024×576三个按钮完整位于窗口内，所有图片加载成功；四态预览已查看，禁用按钮确有disabled状态。实际点击开始按钮只产生样板反馈，URL不变，没有启动应用。两张PNG外角alpha均为0。

目录生成/检查及`git diff --check`结果记STATUS。本批不涉及游戏运行，不运行全项目玩法测试，不冒充真实Godot窗口验收或Git最终Review。标题、按钮与面板组合的观感仍待用户评价；按键音、真实菜单导航、退出处理、暂停/重开回归都未实现。

## 常见错误

- 把文字烘焙到按钮：无法复用，也难本地化；保持无字底图与实时文字分离。
- 用透明图片的整个矩形充当热区：应核对可见轮廓，避免按钮外空白拦截拖动。
- 认为面板底图等于菜单完成：底图仅提供表现，实际状态与授权操作由B接线。
