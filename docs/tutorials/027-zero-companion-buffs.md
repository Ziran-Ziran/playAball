# 零伙伴开局与 Buff 文案

本批按计划010实现：正式游戏开局没有伙伴，外包每级增加一个，最多三个。旧三靶场仍允许摆四球测试接力代数，实验室的显式数量覆盖也保留；不要把开发夹具数量当成正式局规则。

## 文件和调用过程

- `resources/roguelite/upgrades/*.tres`：显示名、解释、类别、等级上限；ID不改。检查器可直接修改标题与描述，数值规则仍在构筑或战斗组件中，改文案不会改伤害。
- `run_build.gd`：外包等级等于伙伴数量；候选池先过滤前提，然后走原有权重与类别多样性抽取。零伙伴不出一键跟随、炸鱼；一个伙伴可出这两项；两个才出接力。
- `run_director.gd`：重开先清构筑再按零数量重建队伍；选奖励后调用 `apply_build()`，由管理器补足队伍。不会为一次升级重摆已有球。
- `companion_manager.gd`：`ensure_count()`保留需要的数量，在主球周围三个距离环、每环八个方向查询实体空间。所有候选都堵住时不生成，战斗物理帧每0.2秒重试；暂停时不会偷跑。重开用 `set_count()`清除旧队伍及旧增员目标。伙伴不在主球中心回退生成。
- `run_hud.gd`：四卡的类别、中文名、等级分行；快速上弦从当前构筑计算冷却前后值，而不是把资源描述当实时数值。卡片仍有原来的入场输入锁。

输入→逻辑→输出：击杀获得真实奖励→在有资格的候选中选择外包→构筑增加一级→管理器查找安全空间→生成一个受真实碰撞规则约束的伙伴。满三级再选会被拒绝；重开清为零。

## 文案与原规则的边界

冲刺！冲刺！、逍遥游、快速上弦、双发、！？肥肥？！、补刀、保龄球、炸鱼、外包、一键跟随、接力、小小的也很可爱、退！退！退！、饱餐、运筹对应原15个ID。只改变外包数量及依赖卡抽取前提；其他伤害、百分比、递归限制保持原实现。炸鱼只由外包伙伴有效命中触发，未扩展到保龄球敌人。接力在未选天赋时已有基础传能，天赋只增加有限补偿。

## 修改与扩展

修改数量上限必须同时核对外包资源的 `max_level`、`DemoBuild.companion_count()`、抽卡前提及测试，不能只改管理器的实验室上限。修改冷却规则要从0到4级逐级确认每级有实际收益；界面预览直接调用同一个构筑算法。地图边界现在由地图接口提供；增员、跟随与出界恢复读取同一边界/安全查询，四图接线见教程029。

## 验证与常见错误

使用本机固定 Godot 4.7.1执行 `tools/verify.ps1 -GodotExe <实际路径>`。`roguelite_build.gd`覆盖0→1→2→3、满级拒绝、重开清零及依赖卡前提；`roguelite_run.gd`覆盖正式局选择、胜负、重开、场地堵塞等待和解除堵塞后的补员；`ui_integration.gd`核对冷却预览。自动状态测试含主动清敌和跳首领，不等于真人通关。

编辑器F5→开始：观察开局零伙伴；首次奖励外包→出现一球；暂停重开→归零。在1024×576检查最长中文标题与四张卡，悬停查看完整描述。测试中用显式构筑给只有一伙伴的队伍塞接力只是开发复现接口，不代表普通抽卡允许。

常见错误：数组为空时仍索引第一个伙伴；管理器把数量夹到至少1；重开沿用待生成数量；出口堵塞时直接放主球中心；文案承诺所有非主球触发炸鱼。这些都与本批规则不符。后续地图移动机关仍需重新验证增员空间，不能用本批旧场地检查替代地图验收。
