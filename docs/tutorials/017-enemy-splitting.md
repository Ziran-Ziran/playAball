# 017：可选的敌球分裂与整族奖励

## 开关与规则

敌球分裂是玩家可选规则，默认关闭。`RunDirector.split_enabled`保存偏好，顶栏“击破分裂”勾选框通过`set_split_enabled(bool)`切换；重新开局保留这个偏好，但不保留上一局敌人、分裂预警或经济。关闭只影响之后的死亡，不删除已经出现的子体及其预警。

开关开启时，波4/5原有重型配额中的每第2只改为6生命，不增加重型种类数量或总出场数量；关闭时仍使用原有4生命重型，不为了一个未启用的选项提高难度。

初始生命至少4的普通敌人死亡，尝试生成最多2颗3生命基础敌球；3生命敌球死亡尝试生成最多2颗1生命基础敌球；1生命不再分裂，2生命炮台不分裂，首领始终不分裂。最多两代子体。数量受当前波次“活敌＋预警”预算限制，所以满场时可能只生成1颗或没有子体。

## 为什么一族只给一次奖励

原始敌人标记`family_reward=true`，其子体和孙体都是`false`。原始敌人的首次死亡给1击杀和1币，子体只增加清场压力，不再刷击杀奖励或货币。开关因此不能变成无限刷奖励的入口。

死亡回调先核对整局修订、节点仍在树中、未结算胜负及`family_death_processed`标记。标记后只处理一次奖励和分裂；重复死亡信号不会复制子体。重开修改整局修订，旧敌人即使被测试重新放回场景，旧死亡回调也无法把子体或奖励带进新局。

## 文件和接口

- `scripts/roguelite/run_director.gd`负责开关、波4/5的少量6生命配置、预警队列、分裂位置、安全检查、死亡去重和整族奖励。
- `scripts/roguelite/enemy.gd`提供`hit_points_override`，0使用种类默认生命，进入树之前设置6/3/1即可生成不同生命的个体。导演记录生成后的初始生命，不能按临死时剩余0血判断分裂等级。实体形状、质量、力与冲量仍由敌人脚本处理。
- `tests/roguelite_splitting.gd`覆盖默认关闭、代数、实际生命、整族经济、重复死亡、安全延迟、预算、清波、旧局回调和首领例外。

`spawn_enemy(kind, point, hp_override=0, family_reward=true, split_generation=0, from_split=false)`保留原有两参数调用；完整分裂经预警物化，不直接调用最后一个参数绕过安全检查。

预警字典增加`hp_override`、`family_reward`、`generation`。次球还携带`split=true`、`origin`和`waited`。普通刷怪/首领召唤缺少这些字段时使用默认值，不要求其它调用者构造整套分裂信息。

## 输入 → 死亡 → 局部预警 → 次球

玩家勾选开关后，死亡回调读取当前偏好；符合生命和代数条件才执行`queue_split()`。预警先放在父体左右约32像素，不传送到远入口，至少持续0.8秒。

物化前`split_point_safe()`核对玩家距离至少80像素、场内边界、半径23的圆形物理空间，以及其它分裂预警之间至少46像素。检查墙、挡板、箱体和活敌人；已死亡父体的RID排除，避免死体尚未移除时把自己的位置误判成障碍。分裂检查走直接物理空间查询，不修改球的位置假装避障。

如果玩家仍贴着或局部被挡，原位置重新预警；累计延后约2.4秒后，才在父体48/88/128/168像素的附近圆环寻找安全点。换点后重新给完整预警，不能刚换点就生成。持续不安全约4.8秒或找不到局部空间，取消这一颗子体，避免玩家贴着预警就永远卡住清波。

分裂子体真正加入前同样检查波次预算。子体只进入待生成队列，不在死亡同帧递归生成；下一代必须等实体出现、被玩家真实击杀后才有机会排队。残留的子体和预警会阻止清波，先处理应得击杀奖励，之后才能进入商店/事件。

## 调参与扩展

检查器的`split_enabled`是默认值，实玩开关可随时改变。当前每代最多2颗、最多2代、3/1生命、80像素安全距离和局部搜索半径在导演对应函数中集中定义。扩展时先修改明确的规则和对应测试，再增加种类或代数；不要把分裂写进`enemy.hurt()`里，否则首领/旧局/奖励去重会更难保持一致。

想调整6生命个体频率，查看`queue_batch()`中波4/5和`_wave_heavies % 2 == 0`条件；不要绕过原有重型配额额外生成一批6生命敌人。想改经济，明确整族总奖励后再修改`family_reward`传播，不能单纯让所有子体默认给币。

## 验证与最短试玩

自动检查使用当前设备实际核验的Godot路径：

```text
Godot --headless --path . --script tests/roguelite_splitting.gd
```

先在旧版本得到缺少可选分裂入口的失败，再实现后23项通过；集成增加3项真实勾选接线检查后共26项，日志为忽略的`.local/splitting-green.log`。测试使用定向生成和手动推进时间，证明规则，不证明玩家觉得有趣或难度合适。

正常打开`scenes/roguelite/run.tscn`按F6；勾选分裂，击杀带4/6生命的敌球，看附近先出现预警，再出现3生命次球，继续击杀后变为1生命。核对整族只有原敌人给一次击杀和货币，子体必须清完才能换波。中途取消勾选，已有子体应保留，之后死亡不再分裂；重开应保留勾选偏好并清空旧次球。

开发快速复现可设`debug_start_wave=4`，但首批不保证立刻有6生命；6生命只来自该波每第2个重型配额。测试脚本可定向生成6生命，不能将这个夹具称为真实通关。完整难度、分裂是否值得开启、画面预警是否清楚，仍需真人试玩反馈。
