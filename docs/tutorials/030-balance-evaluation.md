# 固定种子数值评估与候选保留

评估入口独立于正式菜单，不自动修改正式默认。先通过四图功能门槛，再运行真实刚体、正式发射和接触规则。参数候选只在白名单Resource里改变一组因素；输出到忽略的`.local/overnight`，保留资源差异、逐帧采样和原始事件。

## 组成与数据流

`evaluation_fixture.gd`创建单敌、怪群、墙角、反向纠偏、伙伴链、尖刺/传送六类独立场景。边界、玩家、敌人、伙伴、发射、生命和伤害均是正式物理节点/脚本；机关场景复用正式地图三。初始位置与预选构筑属于固定夹具条件，不冒充自然获得的整局构筑。反向夹具使用较长直线边界，避免初始右发在纠偏输入之前先撞墙反弹。

`input_policy.gd`提供最近目标、安全空间纠偏、伙伴接力三个策略。它们只调用DemoLaunch.launch_with_drag，受到真实冷却、容量、暂停和重置校验。策略不会改速度、生命、伤害或攻击资格。安全策略查询实体路径、预警与尖刺；接力策略只瞄准已有待命伙伴。在无障碍或无伙伴场景，策略的实际方向可能重合，36条组合不等于36个统计独立样本。

`balance_profile.gd`把明确的冲量、反向抵消和基础冷却应用到当前真实对象；每条结果同时存候选参数和对象实际读数。`scenario_runner.gd`按固定种子/策略/20秒物理步串行跑组合，每次完整重建夹具，不沿用上一候选的动量、随机状态或实体。`tools/balance_search.ps1`固定源文件SHA256、输出目录和配置，不覆盖已有批次。

输入策略→正式发射→刚体实际碰撞→统一伤害/伙伴传能→Recorder消费只读事件→逐条JSON→固定规则成对比较。不能把公式推算伤害当成真实接触，也不能直接调用Combat.resolve补命中。

## 采样口径

- effective_damage来自真实敌人hurt事件前后的HP差值，排除溢出伤害；nominal_damage是有效碰撞请求数值，两者不同。
- cooldown_wait只计玩家存活、敌人仍活着、正式发射不可用的物理时间。clear_time保留实际清完本夹具目标的时刻；20秒没清完标censored，不算成功。
- corner_time是70像素边界带内速度低于80的停滞代理，不等于已经证明软锁。
- 反向意图固定在2.35秒开始；策略不因候选不同而改这个时刻，记录方向响应及实际清敌时间。
- 原始contact_outcome保留接受、拒绝原因、攻击链、接触速度和时间；生命变化和每0.1秒位置/速度/冷却也保存。HP包含20秒内清场后仍在运动的尖刺伤害，因此需要正常整局复核，不能仅凭这一项评价难度。

## 实际运行与墙钟速度

工程物理固定120Hz，time_scale保持1。探针用同一单敌/最近策略/种子42分别跑正常墙钟与`--fixed-fps120 --disable-render-loop`：都运行2400物理步、20秒模拟，真实掉血4、击杀1、接受发射1、首次击杀0.86667秒一致；墙钟分别约19.983秒和0.119秒。它只验证这个探针，不声称所有复杂场景与墙钟模式完全等价。候选比较全部使用相同固定步模式，不通过修改物理求解器或time_scale提速。

例如在PowerShell执行：

```powershell
./tools/balance_search.ps1 -GodotExe <本机4.7.1实际路径> -BatchName e-control-r1 -Profiles baseline,control_030,control_060
python tools/analyze_balance.py .local/overnight/e-control-r1
```

每候选为3策略×2种子×6场景×20秒，36条；实际墙钟随碰撞/AI和日志量变化，不能把模拟时长写成真人试玩时长。训练种子42/20261103，留出种子123456；正式采用前还必须跑正常AI完整局与三条从真实卡池选择的构筑路线。

## 固定规则与如何保留候选

`evaluation_rules_v1.json`在候选搜索前写定：物理错误、无限链、总掉血增加和明显坏例优先否决；控制组要求成对平均清敌时间改善至少5%、反向场景改善至少10%、最差成对退化不超过20%，并通过后续留出/整局/成长验证。缺少成长与整局证据时不输出总分，更不以分数冒充用户认可。

比较脚本要求同样的场景、策略、种子、源文件指纹、评估版本。改评分定义必须给新版本并重跑旧候选，不能看了结果再放宽门槛。两轮无改善就检查坏例或转向另一短板；不无穷随机搜。正式默认只在验证后另行接入，失败候选保留为独立资源。

控制组第一轮已真实比较0/0.3/0.6：0.6改善反向与机关场景，但怪群清敌变慢，未过固定门槛，暂不采用。完整原始结果与逐项结论在`.local/overnight/e-control-v2-r1`，后续批次以STATUS/检查点为准。不能把单项提高写成全局手感改善。


## 控制组停止与正常整局代理

控制组第二轮另测0.15/0.45。两个批次的基线36条关键结果完全一致；四个候选均未过预定门槛，维持正式抵消0。0.6平均成对清敌仅改善3.67%，反向改善11.76%，但最差怪群退化22.67%；0.45最差退化40.06%，0.15最差退化96.72%。原因是更强反向冲量改变怪群内后续弹道，单次回头更快不保证整体清场更快。按两轮无改善规则结束这组搜索，保留候选，不调宽门槛。

冷却组另用搜索前写定的`cooldown_rules_v1.json`，目标改为真实有敌期间总不可发射等待降低10%；平均清敌改善5%、最差退化20%、总掉血不增和物理硬门槛维持。它不改控制组已有规则。新的`-Isolated`选项每条种子/策略/场景启动新引擎进程，再汇总36条，避免实例/RID分配历史影响；正常整局也应每条路线用独立进程。

`full_run_agent.gd`复用同一发射策略，按火力/机动/伙伴三条优先级从真实卡池选择，遵守按钮入场禁用期，商店只能花实际赚到的金币，不注入生命、钱币、伤害或清场。自然死亡和480秒截尾原样记录，不写成通关。核心敌人HP、首领核心与模块损失分别记录。

调试时在physics_frame/延后队列恢复SceneTree暂停会触发本机4.7.1的state-query重复入队错误；本地逐项排除渲染开关及卡片等待后，将菜单请求移到正常`_process`，35秒同种子探针无引擎错误。与[Godot官方仓库问题122378](https://github.com/godotengine/godot/issues/122378)描述相符，不升级固定引擎，也不隐藏错误日志。此前带错误的自然局诊断不作通过证据。

正常局还发现主球/伙伴出界恢复给动态地图方法传未标类型数组时会报Array[RID]类型错误；已补真实物理状态复现与显式typed exclusions修复。恢复请求现在可发只读诊断信号，后续正常局继续检查是否出现实体穿墙，不用恢复成功掩盖真正的物理问题。


## 当前采用与未采用

冷却组真实比较2.2/2.0/1.8，每个候选36条隔离进程组合。2.0平均成对清敌改善5.27%、有敌期间等待减少16.96%，但最差怪群退化88.63%；1.8的机关场景存在截尾和总掉血增加，均不采用。正常AI留出种子123456又对基线、控制0.6和冷却2.0分别跑三条真实成长路线，共九局；全部自然死亡在第三波，未伪称胜利。基线没有出界恢复；0.6两次、2.0一次，作为候选额外硬性否决。对应`.local/overnight/e-natural-isolated-v3/comparison.json`。

成长另作84条隔离夹具比较：同种子/策略、同默认物理，单敌和怪群；火力、机动、伙伴各有早期/成型构筑与无升级对照。火力平均清敌从6.70秒降至5.05/3.09秒；机动与伙伴在这些固定策略下没有一致改善。原始结果和构筑列表均保留在e-growth-*，汇总e-growth-comparison.json。不把预置夹具构筑当成正常局直接赠送，也不因输出未增加就谎称升级未实现；机动/接力的收益与策略和弹道有关，仍需真人判断。

本批正式默认保持反向抵消0、冷却2.2、冲量1050。已实际应用并测试的数值候选全部保留为对照，未用平均分掩盖坏例或穿墙恢复。接下来转向危险可读性、角色与卡片反馈等已发现短板，而非无限盲搜。

## 后续实际传能候选：两轮后停止

G1普通包保留后，针对伙伴构筑收益不稳定另立一组传能实验。将原常量0.85显式导出为transfer_retention，正式默认仍0.85。独立资源比较0.75/0.95，第二轮增加0.90；只改接收冲量比例，保留1050传能冲量上限、三代链路、262.5升级接力补偿上限、120来源反冲上限，敌人/危险/冷却/伤害不变。

新的Recorder统计伙伴直接实际HP损失、接触数和激活数。hurt同步发布HP，随后接触结果确认来源；过量3打1只归因1，回声/爆炸不冒充伙伴直接撞伤。新增伙伴越界/非有限值硬门槛。场景夹具补齐跟随、敌攻击范围升级、护身震退及长反向场景伙伴边界，使预选构筑真实生效；此前84条成长构筑不包含这些新补齐的follow/shrink/pulse，原始记录保留，不与新源版本硬拼。

transfer_rules_v1在运行前锁定：平均成对清敌改善5%、伙伴直接HP/有敌时间改善10%、最坏退化不超过20%、总掉血不增、无物理失败。第一轮108条：0.75平均清敌退化42.07%，0.95改善5.33%但最坏退化64.35%且总掉血+9。原单列relay的伙伴被激活，但三只靶均由主球先杀，伙伴直接HP为0，相关速率门槛没有辨别力。两个候选仍独立违反坏例/掉血门槛，不能把未观测速率说成已改善。

按弹道诊断新增独立relay_fan侧向目标，不改变原六夹具；基线预检由伙伴打掉3点中的2点，证明测到了伙伴作用。v2规则保持全部数值门槛，指定该侧向场景为速率目标；基线与旧候选全部同源重跑，并实际加入0.90。第二轮168条，原36条基线的清敌/有效HP/伙伴HP/掉血/输入/链路关键结果完全复现，新增六条侧向目标结果。

## 基础冲量的一轮有界对照

针对首次撞击与弹道效率，另锁定impact_rules_v1，再真实应用945/1155两份资源，与1050基线在原六夹具、三策略、42/20261103种子隔离运行108条。只改冲量；反向抵消0、冷却2.2、传能0.85不变。门槛为平均成对清敌至少快5%、首次实际HP伤害至少早5%、最坏退化不超过20%、总掉血不增加且无物理失败。没有根据结果修改规则。

945平均清敌慢1.01%、首次伤害晚8.74%、最坏退化94.83%，即使总掉血少16仍拒绝。1155首次伤害早8.89%，但清敌平均慢3.89%、最坏退化116.61%、总掉血多1，同样拒绝。两者无物理硬错误。首撞更早不能代表后续弹道更有效，不继续盲搜相邻冲量。失败候选未进入留出/自然局，汇总的pending只表示该后续阶段没有执行，不能当作候选正在等待采用。

原始e-impact-r1保存锁定规则、源指纹、逐条参数/实际冲量/轨迹和比较。累计数值执行708条，成长84条、正常AI9局不变；重跑基线不冒充新增独立样本。正式默认1050/0/2.2/0.85全部保留。

## 收尾覆盖的首领类型边界

最终四图稳定性覆盖前发现safe策略把所有敌人都读成DemoEnemy；实际DemoBoss没有warning_left/pulse_radius。新增真实Game首领场景回归，先复现Invalid access，再用DemoEnemy类型守卫修复，指标检查48项通过。普通敌人的评分/方向公式没有改，旧708次候选结果不重算；此前九局自然代理均未到首领，不夸大为已经覆盖这个边界。

safe名称只代表墙/尖刺/普通预警的有限启发式。首领仍可作为目标且不会报字段错误，但此修复没有增加首领冲撞/震波预测，也没有把代理死亡等同于真人难度结论。正式包不含评估器，这一修复不改变玩家规则或旧包的玩法资源。
