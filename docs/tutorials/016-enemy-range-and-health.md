# 016：离开攻击范围取消攻击，按剩余生命辨敌

用户反馈：敌人蓄力过程中玩家已经离开范围，攻击仍继续；扎堆时也难以判断哪些敌人还剩几血。本次只增加战斗信息与可复现的攻击边界，不做全面UI/角色美术替换。

## 一、文件与职责

- `scripts/roguelite/enemy.gd`：敌人范围判断、蓄力/攻击取消、生命覆盖值与绘制。
- `scenes/roguelite/enemy.tscn`：仍提供刚体、碰撞形状和物理材质，本次不改实体形状或碰撞层。
- `tests/roguelite_enemy_readability.gd`：使用真实敌人组件检查三种敌人的范围边界、重新蓄力、保龄球与生命色阶。
- `tests/roguelite_enemies.gd`：保留既有敌人/弹道回归。其远距离炮台夹具显式设置2000范围，只为测试弹道、出场物理初态和数量上限；游戏默认炮台范围为480。

## 二、输入位置怎样影响攻击

每个战斗物理帧，敌人读取玩家与自己的世界坐标差 `offset`，由 `_within_attack_range()` 判断距离：

| 敌人 | 生效半径 | 默认值 |
| --- | --- | --- |
| 方形脆皮 | `pulse_radius` | 90；威慑升级会缩小 |
| 圆形重敌 | `charge_range` | 180 |
| 三角炮台 | `attack_range` | 480 |

距离等于半径算在范围内；超过半径就算离开。检查以中心点距离为准，不包含双方碰撞形状半径，便于保持原有攻击规则。

进入范围且冷却结束 → 开始完整 `warning_duration` 蓄力 → 释放攻击。只要玩家在蓄力或攻击窗口期间离开范围，`_cancel_attack()` 当帧清空 `warning_left`、`attack_active`、`charge_left`，并清除本次未完成攻击的冷却等待。回到范围后必须重新经历完整蓄力，不能继承离开前的进度。

`_release_attack()` 在真正扣血/施加冲量/生成炮弹前再检查一次范围，避免手动调用或延后释放绕过边界。取消攻击撤销的是危险资格；重敌已经获得的惯性仍交给物理解算，不直接改位置或强设速度。

已经离开炮口的危险弹是独立实体，玩家走出炮台范围不会追溯删除它。它仍沿原方向飞行，由接触、撞墙、寿命或整局清理销毁；因此取消炮台下一次攻击不等于场上所有炮弹立即消失。

受击硬直仍优先保持击退惯性；友方保龄球窗口仍优先保留攻击编号、剩余命中次数及有效时长。范围检查针对敌方蓄力/近战攻击，不取消友方投射资格。攻击帧逻辑随战斗暂停，不推进无敌或其它整局计时。

## 三、生命数字和颜色

敌人的外形继续代表行为：方形脆皮、圆形重敌、三角炮台。`tier_color()` 依据**当前剩余生命**返回颜色：

| 当前生命 | 身体色阶 |
| --- | --- |
| 1 | 青绿 |
| 2～3 | 金黄 |
| 4～6 | 紫红 |

例如6血敌人被打到3血立即变金黄，再到1血变青绿。数字以深色圆底、浅色18号字体绘在身体中心，最后绘制，避免被炮管或预警盖住。颜色辅助快速扫描，数字提供准确读数；不能只靠颜色判断。

默认种类生命仍是1/4/2。新增检查器属性 `Hit Points Override` 默认0，表示使用种类默认值；在敌人加入场景树前把它设成6，才生成6血敌人。这个入口让生成器按阶段少量安排更耐打的敌人，不把所有重敌默认改为6血，也不根据玩家每次升级即时加血抵消成长。

`hp` 是运行时真实生命，受伤/死亡仍走原来的 `hurt()`，没有另存一份“显示生命”。覆盖值只在 `_ready()` 初始化，战斗中改覆盖值不会给敌人回血。

## 四、检查器调参与扩展

打开敌人场景，选择根节点：

- `Warning Duration` 控制完整蓄力时长；取消后重新进入仍从此值开始。
- `Pulse Radius`、`Charge Range`、`Attack Range` 对应三类攻击范围；炮台现在必须进入自身范围才开始预警。
- `Hit Points Override` 控制初始生命，0使用默认种类值。正式刷怪在实例入树前赋值，才能在 `_ready()` 生效。
- `Hit Stagger` 仍控制真实受击后的停攻时间，见 [教程014](014-crowd-impact.md)。

颜色与数字绘制在 `tier_color()`、`_draw()` 中集中维护。更换身体美术时保留剩余生命数字，并避免修改质量、碰撞形状或伤害。以后扩展新敌人，要同时决定其攻击范围和预警逻辑，不能默认为全图攻击。

## 五、如何复现和验证

新回归先在旧实现失败，再实现。固定Godot4.7.1执行：

```powershell
& '<本机实际Godot路径>' --headless --path . --script tests/roguelite_enemy_readability.gd
```

39项涵盖：三类敌人范围外不蓄力、进范围完整预警、离开当帧取消、过期释放拒绝、返回重新完整蓄力、有效攻击确实释放后再取消、已发炮弹不删除、保龄球资格保持；以及默认生命、6血覆盖和受伤跨色阶变化。测试通过直接调用实际组件的物理帧方法稳定复现边界，没有伪称真人躲避攻击。旧敌人37项、收益39项和拥挤物理13项也已复跑退出0。

图形渲染夹具排出三类敌人各1/2/3/4/6血，实际渲染1280×720并读取截图，数字与色阶可见；这只检查固定排列的表现，不代表真实扎堆可读性已经由玩家验收。

最短真人步骤：F6运行 `run.tscn`，靠近方形/圆形敌人触发空心预警，向外发射离开范围，观察预警和危险窗口立刻取消；马上回去，观察完整新预警，不能立刻扣血。炮台距离较远时不应继续蓄力，范围内才预警；已飞出的炮弹仍要躲避。观察4血敌人受伤后颜色变化和准确数字；6血样本由后期生成配置提供，不改变基础开局。

常见错误：

- 只在释放时判断范围：预警会在玩家离开后继续，缺少即时反馈。
- 只清 `warning_left`：重敌可能仍保留危险的 `charge_left` / `attack_active`。
- 取消时删掉全部危险弹：会把已经发出的独立攻击也追溯抹掉，破坏原来的弹体规则。
- 把身体颜色绑定初始上限：受伤后颜色不变，无法表达剩余生命。
- 敌人入树之后才赋生命覆盖值：已经完成初始化，数字不会按覆盖值重建。
