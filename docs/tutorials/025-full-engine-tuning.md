# 025：完整引擎与玩法调参台

用户要求把引擎中能操控的量完整开放。现在F1默认进入“完整属性”，从当前Godot构建的属性元数据自动生成目录，不再由9项快捷滑杆决定覆盖范围。原快捷面板仍可通过顶部模式切回。

## 现场使用

启动完整调参EXE或F6运行`tuning_run.tscn`，F1收起/展开。顶部分为“完整属性/常用手感”，下面按分类筛选，再输入中文或原属性名搜索。每页20项，用上一页/下一页翻页；每项带对象、完整属性路径、生效时机和单项复位。

数字直接改，布尔用开关，枚举用下拉，颜色用取色器。向量填JSON数组如`[0, 1]`，矩形用`[[x,y],[宽,高]]`，分波参数用数组如`[6,5,4,3,2]`，回车或点“写入”。类型错误、非有限数、无效质量、零相机缩放等不会冒充生效；被拒绝的数字框回到实际值。

`F9`或“恢复基线”恢复当前启动时的高级属性和固定的9项快捷基线，常用暂停、对照、复制、保存/加载仍保留，且覆盖完整属性。完整属性是明确覆盖值，优先于快捷基线及玩法自动重算；单项复位后回到原玩法/快捷规则。

## 覆盖范围

- Engine：物理帧率、每帧最大物理步数、帧率上限、时间倍率、物理抖动修正等实际公开属性。
- PhysicsServer2D：完整9项SpaceParameter，包括求解迭代、接触回收半径、允许穿透、偏置、线性/角速度休眠阈值、休眠时间。
- ProjectSettings：当前构建加载的全部有具体值的工程设置，包括物理、显示、渲染、音频、输入与平台设置；未标记EDITOR的设置也列出。
- 主球/伙伴/三类敌人/首领/炮弹/白饭：原生刚体、材质、碰撞形状、节点属性，以及所有脚本`@export`参数。尚未生成的敌人/首领通过独立原型提供参数入口；后续新生成和分裂子体继承设置。
- 发射、伤害/接力、生成、生命、白饭管理、护身震退、奖励、阶段、升级资源权重/文案、音频、镜头/碰撞表现，以及其余当前场景节点。

本机Godot4.7.1源码环境的一次枚举为7838条对象属性/设置，其中948条工程项；同名字段在不同对象上分别列出。数量随构建和场景变化，以面板计数为准，不把只读对象引用算成可调数值。对象引用、脚本/资源身份、引擎标记只读的字段会明确标只读；资源内部可编辑值会继续展开。没有公开属性接口的编译期常量不会伪造成可调项。

## 生效时机

1. **即时**：当前对象配置、Engine属性、已映射的世界重力/阻尼和物理空间参数。重力倍率为0的刚体仍不受环境重力；可在主球原生属性中修改`gravity_scale`。
2. **下一物理帧**：刚体位置、旋转、速度等一次性状态编辑；暂停时先收起面板或关闭调参暂停。走`PhysicsDirectBodyState2D`接口，不会每帧钉死运动；正常复位会取消未应用的旧请求。
3. **新生成/重开**：初始生命、首领模块生命和敌人类型等初始化参数；不会中途把当前生命当成初始值重新填满。玩家生命上限在重开后应用。
4. **后续规则读取**：奖励权重、阶段定义等，当前已显示的报价/选项不追溯重抽。
5. **保存后重启**：只在启动时读取的工程设置。只调用`ProjectSettings.set_setting()`不等于热生效；这些字段明确标重启，不虚报当前画面已改变。

Engine物理帧率和对应工程设置共享同一台账，改哪一个入口都同步；退出调参场景恢复原全局值，避免污染别的入口。

## 保存、重启与还原

“保存参数”生成EXE旁的`handfeel_preset.json`，schema2包含9项基线和高级覆盖；旧schema1文件仍能读取。高级值使用Godot无对象Variant编码保留向量、颜色、字典、定型数组的类型，不执行表达式，也不允许反序列化对象。UI编辑复杂值时仍使用可读JSON。

工程设置另写入EXE旁的`override.cfg`，下一次启动由Godot加载；只改这次选中的键，并保留文件中其他设置。完整目录底部“清除重启覆盖”删除本工具拥有的配置键，重启后回到工程原配置。加载JSON只更新内存；需要让重启项生效时，再保存并退出重开。`F9`恢复当次启动基线，不会偷偷删掉磁盘上的重启配置。

正式工程文件、原`.tres`与A素材均不写回。初始发给策划的ZIP不包含本机验收时的参数JSON或override.cfg。

## 文件与调用

- `live_tuning.gd`保留快捷基线、暂停和用户动作，接入完整目录；高级覆盖优先，防止快捷值每帧把它覆盖掉。
- `lab/full_tuning.gd`枚举对象/资源、生成元数据、校验/应用/复位、原型和新生成接线、跨别名全局恢复。
- `lab/engine_tuning.gd`把工程设置映射到实际Engine/PhysicsServer接口；管理重启配置。
- `lab/tuning_variant.gd`验证JSON形状和类型，处理复合值与无对象序列化。
- `lab/full_tuning_view.gd`分类、中文/原名搜索、分页和按类型生成控件；只创建当前页。
- `combat_body.gd`的一次性调试状态接口在物理回调消费；未发请求时原物理流程不变。

原型位于禁用处理、独立World2D的SubViewport中，不混进正式围场。编辑资源时沿路径逐层复制，修改碰撞半径或主题不会污染共享场景资源。新增`@export`或引擎公开字段会自动被枚举，无须再手写一条滑杆。

## 扩展与验证

新增一类运行对象，在`setup()`登记稳定角色名并接入生成事件；新增仅启动时读取的设置保持“重启”标记，只有补实际运行时适配和读回测试后才改成“即时”。调面板位置、字号和默认模式可改`tuning_panel.tscn`及对应视图脚本。

运行`tests/roguelite_full_tuning.gd`：覆盖目录完整性、原生惯量/CCD、嵌套材质/形状隔离、当前与未来实体、出生生命、求解器实际读回、Engine与工程别名两个顺序、向量/颜色/定型数组、错误JSON、原物理状态复位、重启配置保留/清除。旧40项快捷面板回归继续运行；两套均接入verify和CI。

实窗检查搜索`mass`、`gravity`、`speed_limit`，编辑一项并收起发射；保存、复位、加载再比较。只有自动检查和真实窗口都核对后才交付，不把字段枚举数量当成所有组合已经试玩通过。

官方依据：[ProjectSettings运行时说明](https://docs.godotengine.org/en/stable/tutorials/editor/project_settings.html)、[全局重力运行时接口](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html#class-projectsettings-property-physics-2d-default-gravity)。本地实际API以固定Godot4.7.1探测及回归为准。
