# 013：阶段、商店与补给事件

## 为什么把五波分成阶段

击杀奖励让球在战斗中持续成长，休息区则让玩家在压力间歇决定如何使用资源。当前沿用五波和首领，不创建新地图：波1～2后是商店，波3～4后是补给事件，波5后直接挑战首领。这些数量和价格是计划006的建议值在本地原型中的实现，尚未通过真人节奏与平衡验收。

开局仍只有基础主球、1颗不跟随的小弟、5点生命、0币，没有局外继承。后续波次使用原有更短刷怪间隔、更多敌人和敌人组合增加压力，没有按玩家每次选奖励即时补强敌人生命。

## 文件和节点

- `scripts/roguelite/stage_definition.gd` 定义阶段标题、首末波和阶段结束后的内容；`resources/roguelite/stages/stage_1.tres`～`stage_3.tres`保存配置。
- `stage_flow.gd`读取上述资源，提供`rest_after(wave)`及`stage_number(wave)`。它不移动球、不扣血、不购买商品。
- `run_wallet.gd`保存余额和已结算死亡ID，只在同一有效死亡首次结算时加1币。
- `run_director.gd`拥有钱包和阶段流程，协调战斗、领奖、商店、事件、准备倒计时、胜负。`run_event`只通知音频等表现消费者。
- `scenes/roguelite/rest_panel.tscn`是可编辑的遮罩、面板、标题、说明和按钮容器；`rest_panel.gd`显示报价并发出`action_selected(action, revision)`。此面板是流程原型，完整UI样板已被用户否定，按最新要求暂停全面美术替换、优先功能。
- `tests/roguelite_stage_flow.gd`与`roguelite_shop_events.gd`验证阶段和交易规则。旧`roguelite_run.gd`关闭阶段休息，继续单独覆盖五波底层推进；新测试覆盖默认启用的阶段流程。

## 输入 → 规则 → 画面

1. 普通敌人死亡，经整局死亡回调进入`register_kill`。击杀奖励组件先去重；首次有效死亡同时向钱包入账。首领死亡直接胜利，不额外给普通击杀货币。
2. 清波时，必须已停止刷怪、没有活敌人和生成预警。`advance`先处理死亡和待领奖，再判断波次边界。波2/4进入休息，其它波继续，波5进入首领。
3. 休息锁定发射，暂停战斗树、生命无敌计时、能力和冷却。面板本身始终处理输入，Esc不能把休息关闭并跳过流程。
4. 点击商品或事件只发出ID和当次报价版本；导演核对状态、版本、库存、余额与生命，再结算。UI不保存第二份玩家生命或货币。
5. 商店可直接继续；事件选择治疗、免费成长或跳过。进入`TRANSITION`后显示3秒倒计时，只有导演继续处理这段时间。倒计时结束取消旧瞄准，恢复物理，排入下一波原有安全生成预警。

这里有两种不同的暂停：战斗中领奖保留飞行中的危险弹和球的动量；阶段结束休息清除上一阶段危险弹、白饭和旧回声。不要把两者合并成“打开任何面板都清场”。

## 商品与奖励来源分离

商店的两件商品各限购一次：4币恢复2血；8币从当前合法奖励池选一次成长奖励。满血不能买治疗，余额不足显示原因，可不消费直接离开。事件提供恢复2血、免费选一次成长奖励或跳过，每次只结算一个选项。计划006原建议的事件6币在最后阶段没有消费入口，因此改为能立即生效的免费成长。

```gdscript
if not wallet.spend(price):
	return false
shop_bought[id] = true
```

状态、报价、库存和治疗资格均先检查，随后在同一同步调用中扣钱并记库存，没有异步等待让两次按钮点击穿插进交易。钱包拒绝负价和余额不足。UI禁用只是提示，代码仍要再次检查，不能信任按钮状态。

选卡使用`reward_source`区分`kill`、`shop`和`event`。后两者复用三/四选一画面和合法候选计算，但不调用击杀奖励的`consume_reward()`，也不增加击杀领奖次数。购买结束回商店，事件选卡结束进入3秒准备；两者都保留累计击杀进度、待领奖队列和首次击杀奖励的新同伴保证。不能把购买或事件直接伪装成“又击杀够一次”。事件进入选卡后状态已切换，旧事件按钮无法再次发奖，旧卡片版本也不能重复升级。

`rest_revision`在进入休息、开始过渡、重开、调试跳波及结算时变化。按钮保留生成时的版本，旧局或旧休息面板的点击会被拒绝。`_choice_revision`继续保护三/四选一卡片。库存不因刷新面板而重置。

## 为什么清理攻击资格但不瞬移球

阶段结束清掉危险弹节点、白饭、待执行回声及回声修订、接触配对；伙伴调用`end_attack()`退出临时攻击，主球清发射链编号，护身震退计时重置。球的位置和速度保留，休息时依靠树暂停保持物理状态，不逐帧设置位置，也不因为显示商店而瞬移回原点。整局重开仍走原有`reset_body()`和物理状态接口。

## 检查器如何调参

打开`run.tscn`选择`RunDirector`：

- `enable_stage_breaks`默认开启；关闭可对照旧五波连续流程，不能把关闭后的测试说成验证了阶段。
- `heal_price`、`upgrade_price`分别是治疗价、成长价；默认4/8。补给事件免费二选一或跳过，不提供无处消费的末段货币。
- `transition_duration`默认3秒，控制休息后的安全准备时间。
- 原有`spawn_duration`、`spawn_interval`、`enemy_limit`仍控制战斗压力。先调组合与频率，再考虑生命，不用增加敌人血量完全抵消玩家成长。

阶段首末波与休息类型在三份资源中调整；修改末波时保持区间连续且不重叠。`first_wave`目前用于显示所属阶段，实际推进仍按波号加1；它不是任意跳地图的入口。若新增第4阶段，还要更新`stage_flow.gd`的资源列表并补边界测试。

扩展商品时先增加交易分支和原子校验，再添加报价按钮与测试。扩展事件时先明确一次性结算、满血与不足资源规则。不要只改文案就让同一按钮反复加钱。当前没有刷新、利息、存档、永久成长或随机路线地图。

## 最短复现与验证

正常入口是打开`scenes/roguelite/run.tscn`按F6。击杀并选奖励，清掉波1～2，进入商店；购买或继续后观察3秒准备、波3～4、补给事件、波5与首领。观察成长是否有价值、钱是否够用、休息是否过长，记录两局实际战斗/选择/休息用时和结果，才可以判断节奏。

开发定向复现可把`debug_start_wave`设为2或4，缩短`spawn_duration`，清光敌人与预警后观察休息；这是测试入口，不能冒充实际完整游玩。检查器修改开局波次后记得恢复1。`debug_wave(2/4)`也可用于本地测试脚本；直接`enter_rest`仍会拒绝未清场、有预警或待领奖的状态。

自动运行（使用本机实际核验的Godot路径）：

```text
Godot --headless --path . --script tests/roguelite_stage_flow.gd
Godot --headless --path . --script tests/roguelite_shop_events.gd
```

本次两套分别21项和12项通过，覆盖清场/预警/待领奖边界、残留攻击清理、冷却暂停、Esc不能绕过、倒计时、事件成长实际生效与一次性/旧卡保护、击杀经济不变、首领推进、重开、唯一入账、满血/不足余额、库存和旧报价。日志在忽略的`.local/stage-green.log`及`.local/shop-green.log`。测试禁音，不是音质、视觉或真人节奏验收。

常见问题：休息没弹出先看预警和残敌，再看是否有待领奖；买不到治疗先看是否满血或已买；旧按钮失效是报价防重保护。若暂停后不再继续，核对`RunDirector`处理模式为Always，战斗实体保持Pausable，不能为让倒计时走动而恢复整个战斗树。
