# 事件音效：制作、接线与试听

本教程对应计划006的音效整改。新声音由项目内原创PCM合成，没有下载或拆包素材。自动检查证明调度和样本数据正确；是否好听、是否刺耳和能否在战斗中辨认，仍需用户在真实设备试听确认。首版真实试听被用户评价为“太温和、不够爽”，未通过；现已加强重撞和击杀的冲击结构，当前版本待复听。

## 文件与节点

- `scripts/roguelite/audio_palette.gd`：负责短声音的波形制作和缓存，不读取生命、伤害或敌人状态。
- `resources/roguelite/audio/default_palette.tres`：可编辑音色资源，`sample_gain`控制合成样本振幅。
- `scripts/roguelite/audio_director.gd`：接收事件，挑选变体、限制频率和声部，并播放音频。
- `scripts/roguelite/audio_preview.gd`、`scenes/roguelite/audio_preview.tscn`：独立试听入口，不运行或修改战斗。
- `tests/roguelite_audio.gd`：检查事件、重复回避、并发、静音、暂停、重开和PCM数据。

整局使用独立音频节点接收机制事件。`impact_feedback.gd`继续控制环、粒子和震动；声音路由不参与伤害判断。F5旧侧视与arena三靶场可保留旧音频接口。

## 输入→逻辑→输出

真实机制产生一次事件，例如玩家受伤、敌人死亡或成功确认升级；调用 `audio.play_event(&"hurt")` 后，导演检查音量、暂停状态和同类冷却，再从对应音组选择一个与上次不同的样本。接受事件返回`true`，限频、静音或预算拒绝返回`false`。声音被拒绝不会改变游戏结果。

| 事件ID | 用途 | 变体数 |
| --- | --- | --- |
| light / heavy | 轻碰 / 重撞 | 各3 |
| kill / launch | 击杀 / 成功发射 | 各3 |
| hurt / rice | 玩家受伤 / 白饭 | 各2 |
| upgrade / stage | 升级确认 / 阶段完成 | 各2 |
| victory / defeat | 胜利 / 失败 | 各2 |

不应为空拖、取消、冷却完成或同次重复死亡播放命中声。机制仍负责原有接触与死亡去重；音频导演的限频只是第二层听觉保护。

## 为什么不再只有一个变调正弦

轻碰和重撞分别有3种长度、基频和共鸣组合。合成时叠加低频主体、快速衰减的非整数倍共鸣和经过平滑的弱噪声，区分木质轻碰与低沉重击。第二版重撞加入约13～26毫秒的快速低频下坠、中频硬瞬态和受控软饱和；击杀叠加短破裂噪声与低频爆裂，升级音符的尾音更饱满。轻撞仍保持轻，整改不只是抬高总音量。发射采用柔和扫频加气流，受伤采用下降低音；奖励、拾取和阶段使用短和声音符。

PCM是16位、22050Hz的单声道短声音。开头约4毫秒渐入、结尾衰减至零，减少突变点击；UI音符独立渐入/衰减，不直接改变已有正弦相位。每个样本只合成一次并缓存。`pitch_scale`只在0.98～1.02内变化，音色差异主要来自样本自身。

## 并发与音量

默认最多8声部。普通事件只能占其中6个，给受伤、拾取、确认和结算留出空间。重要事件在满预算时替换较低优先级声音；普通事件不会挤掉受伤提示。重撞优先级高于轻撞，可在6个普通声部已满时替换一个轻撞，但仍占普通预算；受伤与UI优先级继续高于重撞。普通事件同组至少间隔0.10秒，关键事件至少0.12秒。普通声越密集，新增声音越轻；关键事件出现会压低已有普通声。

导演和独立试听默认SFX音量0.65，UI音量0.70；run入口两个滑条均默认0.65。`set_mix(sfx, ui, muted)`同步影响已有声音；主静音会立即停掉所有声部。`set_audio_paused(true)`停止战斗声音，拒绝新的碰撞声，同时保留奖励/结算UI声音。`reset_audio()`清空声部、限频与变体历史，并恢复接收战斗事件；整局重开调用它，避免旧声音串入下一局。

## 在检查器中修改

选中整局的音频导演节点可调整`max_voices`、`sfx_volume`、`ui_volume`与`muted`。展开`palette`资源修改`sample_gain`。音色资源建议在进局前修改，运行时已有PCM缓存不会自动重新生成；停止并重新F6即可比较。先保持混音音量一致比较音色，不能只用降低总音量掩盖刺耳问题。

增加音色时，在palette的事件表与分支中定义样本，再确定该事件是否属于导演的UI/关键事件。机制只调用事件接口，不在音频脚本中添加扣血或奖励逻辑。增加新事件后补调度测试和独立试听列表。

## 最短试听

1. Godot打开`scenes/roguelite/audio_preview.tscn`，F6。默认依次听10类事件，再听10秒密集连锁；中间包含受伤和升级。
2. 按1～0重复单类：1轻、2重、3击杀、4伤害、5白饭、6升级、7阶段、8胜利、9失败、0发射。Space重播全序列，M静音，Esc退出。
3. 观察轻重能否区分；轻碰是否反复同一音色；密集10秒是否刺耳、音量是否忽然堆高；受伤与升级能否穿过碰撞被听清。
4. 回到`run.tscn` F6，确认真实受伤、白饭、击杀和选卡时机；暂停/重开不留旧碰撞尾音。独立试听不证明战斗接线或真人通关。

记录实际使用耳机/扬声器、系统输出设备、音量、WASAPI错误与主观结果。当前音质待用户确认；自动测试不作为“不刺耳”的证据。整改前参考在忽略的`.local/audio-before.wav`，是本机30秒原声音对比，不能提交为正式素材。

## 自动验证与常见问题

使用本机核验的Godot4.7.1标准版运行：

```powershell
& <本机Godot可执行文件> --headless --path . --script res://tests/roguelite_audio.gd
```

Windows GUI可执行文件需要等待进程退出再读取退出码；整库使用`tools/verify.ps1`。

- 完全无声：先检查系统输出、SFX/UI滑条和主静音，再检查音频日志，不能用headless成功断言声卡可用。
- 受伤声被撞击吞掉：核对导演节点是否被正确接线，不要再调用旧`play_sound`制造额外不受预算限制的声音。
- 奖励确认声音消失：确保暂停只清理战斗声，且导演使用`PROCESS_MODE_ALWAYS`；不能让整棵战斗树暂停顺便吞掉UI提示。
- 重复调用声音被拒绝：同组限频是预期行为；真正需要不同含义时应新增事件，不绕过限频堆声部。

整局run入口的两个音量滑条当前都初始化为0.65，覆盖导演UI默认值；独立audio_preview仍是SFX0.65/UI0.70。比较试听与实战时请注意这个差异。
