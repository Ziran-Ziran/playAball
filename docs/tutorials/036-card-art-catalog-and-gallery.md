## 打开样板

Godot4.7.1标准版打开工程，再打开`scenes/roguelite/card_art_gallery.tscn`按F6。F5仍是正式菜单，本场景不改变正式选卡或战斗。顶部可按成长筛选，查看同系列等级；按钮及左右键翻页，3/4键或切换按钮改变每页张数。

卡片显示类别、标题、插画、当前→下一等级、真实收益、资源说明和候选状态。图鉴不会真的选择升级、生成伙伴或发射球。饱餐以3/5生命为明确标注的展示示例；强身展示首次5→6上限，可重复项共用插画，不无限生成等级图。

## 为什么是28张

每个有限等级单独出图；max_level=0的饱餐/强身各用一张共用图。真实来源是resources/roguelite/upgrades，catalog须与它一致。

| 系列 | 图数 | 视觉变化与限制 |
| --- | ---: | --- |
| 外包 | 3 | 主角外加1/2/3个伙伴，伙伴数必须准确 |
| 快速上弦 | 4 | 同一空槽机构的弹簧与回弹笔触；不能变成更多弹药 |
| ！？肥肥？！ | 3 | 软垫局部浅凹→深凹→更强折叠；人物/物理体型不放大 |
| 冲刺！冲刺！ | 3 | 起点压缩、短方向笔触和释放层次逐级增强，无火箭 |
| 逍遥游 | 3 | 短滑痕→长弧→开放S形长滑痕，无翅膀/飞行 |
| 小小的也很可爱 | 2 | 敌人身体不缩，地面攻击范围线收紧 |
| 其余10项 | 10 | 保龄球、运筹、双发、补刀、炸鱼、跟随、饱餐、震退、接力、强身各1张 |

同系列的相邻等级用前一级图作编辑参考，并使用认可的圆眼母版约束身份、眼神与画法。生成式编辑仍可能有细微构图/笔触漂移；缩图时快速上弦和重击的等级细节是否足够明显，保留给用户审美判断，不声称像素一致。

## 生成与修正记录

用户确认圆眼v2后授权进入P2，沿用此前无限生成预算。旧计数不重置：首轮6个图片输出、定向眼神修改3个，再加P2的27个，累计36个实际图片输出，最终卡面仍为28张。多出的历史/失败候选留.local，不混入正式索引。没有未知或等待返回的生成请求。

每次先记录asset_id、prompt、引用及哈希，再调用内置image_gen；结果保存至项目和.local原始候选。已有请求记录时不盲目重发；新语义修正使用独立记录，并保留被替换图。

两处自查修正：双发初稿同时画了两颗储能珠和两颗空中珠，修正后只保留槽内两颗；接力初稿擅自加入蛋糕，改以主角和两个伙伴的两个局部接触点表达物理传递。原稿标为received_superseded，原图、哈希和修正prompt均保留。它们是本Agent的局部自查，不是独立Review或用户认可。

## 检查器里怎么调

- 卡图大小：单卡场景的Illustration最小高度128、垂直扩展与KEEP_ASPECT_CENTERED；留出标题、等级和文案，不裁掉人脸或伙伴数。
- 小图清晰度：PNG Import启用mipmaps、size_limit=512；Illustration纹理过滤为LINEAR_WITH_MIPMAPS。初次直接缩1536源纹理出现锯齿，开启上述采样后实际窗口改善，前后截图都保留。
- 标题/说明：单卡Title字号20，Benefit15，Description14；可编辑对应节点和边距，改后检查最长标题及四卡布局。
- 每页张数与数据：图鉴根节点的columns和catalog_path导出项；不要修改正式Buff资源来迁就图片布局。
