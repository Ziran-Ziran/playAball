# 地图机关、受控传送与旧场地接口

本文介绍可复用的真实物理机关。后续四图已接正式整局，接线与验证详见[教程029](029-four-map-run.md)。本篇组件阶段的功能几何不代表最终位图美术验收。

## 组件与节点

`scenes/roguelite/mechanisms/`中的每个场景都可用编辑器打开：

- `pivot_paddle.tscn`：Anchor静态轴、Paddle刚体、Pin真实关节。碰撞冲量交给物理解算，脚本不按动画强行改动态刚体位置。`pivot_body.gd`在`_integrate_forces`中处理显式复位、转速上限和相对初始角度的限位；参数与回归见[教程033](033-paddle-response-and-feature-checks.md)。
- `moving_barrier.tscn`：Body是AnimatableBody2D，物理帧按正弦轨迹往返。检查器调`travel`、`period`、`initial_phase`。
- `rotating_arc.tscn`：16段可编辑凸四边形组成240度圆弧；视觉多边形与碰撞使用相同点，120度缺口是真空缺。检查器调角速度和初始角度；修改厚度或半径必须同时修改每段碰撞和视觉，不能只缩视觉。
- `spike_strip.tscn`：Area2D检测真实玩家接触，交给同一DemoHealth.hurt处理共享无敌时间。伙伴和敌人不触发玩家远程扣血。检查器的长度/深度用于绘制、安全查询和运行时独立Shape；编辑器中也须同步Shape尺寸及偏移，见教程041。
- `portal_pair.tscn`：A/B是可编辑入口标记，默认相距800。检测玩家、伙伴、普通敌人的真实运动线段，排除首领及弹体。`portal_radius`、出口朝向、间距、安全边界和再入冷却可调。

每个运动机关有`set_active()`和`reset_mechanism()`；暂停使用PAUSABLE，地图状态接口也可以显式停机关。刚体暂停保留动量。视觉形变不得改变碰撞体。

本批回归实际发现并修复两项机关问题：AnimatableBody2D默认延后同步会在停用后多走一步，物理帧手动运动场景现关闭`sync_to_physics`，并用真实推球验证没有失去碰撞；子节点关节先于父节点ready建立锚点，偏心摆位后须重新连接Pin的Paddle端，避免错误地把刚体中心拉回轴心。

## 输入→规则→物理输出

玩家撞挡板→刚体收到真实冲量→关节保住轴心→挡板转动。移动和圆弧由物理帧驱动AnimatableBody2D，不冒充可撞翻转刚体。

接触尖刺→尖刺只核对真实主球→生命组件核对死亡与无敌时间→成功才发`player_hit`反馈事件。视觉不决定扣血。

进入传送门→检查白名单与成对门锁→按身体半径找出口→查询墙/实体/待命伙伴及同帧预约→DemoBody.request_teleport仅保存请求→下一物理状态接口再次检查出口和存活→只改变transform.origin。线速度、角速度、攻击链、代数、伙伴剩余攻击时间与发射冷却保持。退出后必须离开两个门的范围且冷却到期，才可再次进入。

出口堵塞拒绝搬移并发布`exit_blocked`；不能硬塞墙内、清速度或复用reset_body。两个身体同帧进门分别预约出口，间隔按最大普通敌人体积留位。请求后才出现的障碍和同帧死亡也会阻止落地。复位、空间调试编辑、地图释放和显式停用会取消旧请求。集成新地图时，所有暂停/奖励/商店/结算转换都必须调用地图停用接口，不能只依赖树暂停后再恢复旧请求。

## 地图接口

`map_definition.gd`是Resource数据契约，含边界、主球/首领出生点、四个敌人入口和安全区域。`legacy.tres`描述旧围场，`RunDirector.setup`挂接`map_controller.gd`。`point_safe`同时检查身体半径、真实实体、尖刺区域和层为0的待命伙伴；`find_safe_point`确定性搜索邻域，无处可放返回INF，调用方必须等待或报告，不得使用这个值生成实体。

legacy资源保留旧场地的数据契约；现有MapController已实现四图替换、安全出生及机关状态接口，详见教程029。独立实验室仍保留其固定夹具。

## 如何验证和扩展

执行`tools/verify.ps1 -GodotExe <本机固定4.7.1实际路径>`；本批加入map_mechanisms、portals、maps三套，CI本地配置同步加入，但未上传执行。用例先真实失败再实现，保留`.local/overnight/*-red.*`。

机关测试验证偏心冲量确实转动、轴心约束、暂停/复位、最快最慢参数和主球尖刺共享无敌时间；门测试覆盖高速实际穿越、保留运动状态、两体同帧出口、堵塞复核、同帧死亡、重开/停用取消、真实往返和空场清理。夹具使用工程120Hz物理时间，不能把30帧直接当0.5秒。自动测试不等于真人打完整局。

本地`capture_mechanisms.gd`运行实际Compatibility渲染夹具并保存`mechanisms-runtime.png`。它是组件阶段的功能画面；正式四图画面和流程验证另见教程029，不以组件截图代替地图验收。

常见错误：把可撞翻转做成电机动画；传送调用reset_body导致失速/丢链；只检测Area重叠漏掉高速越门或层为0的待命伙伴；按小伙伴半径留出口导致主球与伙伴同帧重叠；只在请求时检查出口；暂停后恢复早已失效的请求。扩展白名单、改变速度方向或添加危险功能都应单独定义和测试，不能在换贴图时暗改。
