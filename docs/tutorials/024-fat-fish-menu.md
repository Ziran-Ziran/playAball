## 图层与显示过程

背景铺满16:9画布 → 左侧少量暗色遮罩保证可读 → 标题左上 → 右侧地面接触影 → 已认可角色 → 左侧开始按钮/次级操作 → 演示反馈。角色不进入碰撞或玩法流程。

主要布局值：标题左5%/上13%/宽45%；角色高95%/右1%/底5%，源图内部透明留白使鞋底落在画面下部地面；开始按钮左8%/上51%/宽36%/高16%；设置与退出容器左8%/上70%/宽36%/高14%，两枚平分宽度、间隔3%。标题和角色使用原比例；按钮容器只裁透明留白，源图不被重画。

按用户明确要求，当前三枚固定菜单按钮的文字与图标已画入贴图；CSS播放三角与可见文字层已移除。`aria-label`保留“开始游戏／设置／退出”语义命名，不产生可见覆盖。悬停提亮，按下下移2像素，键盘焦点有可见外框。点击只显示“美术小样，功能尚未接入”，不会启动/退出游戏或写设置。此约定仅覆盖这三枚固定菜单按钮，生命、余额、卡片等级等实时数据不烘焙。

## 怎样手动调整

双击HTML看组合。调整`.title`、`.character`和`.start`的百分比可移动独立素材；先保证角色轮廓和按钮互不遮挡。当前固定按钮图案与文字都在PNG里，改文字需另生成对应语言/版本贴图；同时更新按钮语义命名和请求映射，避免显示文字与实际动作不一致。

当前没有Godot场景/检查器参数；B后续接线时可建立独立表现场景，将贴图、锚点、安全边距、字号和按压幅度暴露到检查器。正式开始/设置/退出分别发请求，由状态机执行；菜单不得直接修改生命、奖励、阶段或物理。角色与背景不接管鼠标，实际按钮才独占输入。退出、返回、设置持久化等功能需另外明确实现范围。

背景透视只属于主菜单插画，不得据此修改正式俯视地图、墙体碰撞或相机。已有血条/卡框/战斗场地的认可不在这批中重做。

## 常见错误

- 把标题当普通Label重做：会丢掉独立标题的字形；实际本地化另做对应标题或明确回退方案。
- 背景过亮抢角色：先调低背景对比或局部遮罩，保留角色蓝白辨识，不给角色整体套绿滤镜。
- 图片透明留白变成按钮热区：正式控件要让点击范围贴合可见面，不占用周边空白。
- 用户认可角色后直接认定整屏完成：标题、背景、按钮和组合是本轮新试验，逐项收集反馈。
