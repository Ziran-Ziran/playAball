# 教程011：玩家生命面板

完整游戏入口仍是 `scenes/roguelite/run.tscn`，在 Godot 打开后按 F6。左上面板显示生命条、当前/最大生命以及文字状态；这是计划006的基础可读性整改。完整主题、角色和奖励/商店美术仍按 [计划007](../plans/007-ui-art-direction.md) 先出样板，再根据反馈替换。

## 一、为什么只有一份生命数据

`scripts/roguelite/player_health.gd` 的 `DemoHealth` 管理真实的 `hp`、`max_hp` 和受伤无敌时间。伤害、治疗与强身升级都修改这一份数据。HUD 只负责读取和展示，不保存另一份可以扣血的“界面生命”，也不通过填满进度条来治疗玩家。

文件和节点分别负责：

| 文件/节点 | 用途 |
| --- | --- |
| `scripts/roguelite/run_arena.gd` | 整局初始化后，调用 `$RunHUD.bind_health(director.health)` 接线；将原有进度与控制移到生命面板右侧 |
| `scripts/roguelite/run_hud.gd` | 订阅生命信号，刷新条/数字/状态，保留三选四选、结算和重开按钮 |
| `scenes/roguelite/run_hud.tscn` | 保存可在编辑器调整的面板与样式 |
| `Overlay/PlayerPanel/Content/Heading` | 肥鱼名称与 `HealthValue` 数字 |
| `Overlay/PlayerPanel/Content/HealthBar` | 实际生命比例，独立同步最大值和当前值 |
| `Overlay/PlayerPanel/Content/HealthState` | 受伤、恢复、无敌、低生命、倒下等文字提示 |
| `Overlay/Panel` | 原有奖励/结算交互面板，与常驻生命面板分开 |
| `tests/roguelite_hud.gd` | 直接使用真实生命组件的行为回归 |

## 二、从伤害到画面的过程

1. 危险攻击调用 `DemoHealth.hurt()`。它先判断死亡、非法伤害和无敌时间，只有真正扣血才发出 `changed(hp)`。
2. `bind_health()` 将此信号接到 `_on_health_changed()`。HUD 比较上次显示值，生成短暂的“受伤 -2”或“恢复 +2”文字。
3. `_refresh_health()` 每次从组件读取 `max_hp` 与 `hp`，分别赋给进度条上限、当前值和数字。因此强身增加上限时，不会只改数字而漏改比例。
4. 无敌倒计时结束没有另一个 `changed` 信号，因此 HUD 在 `_process()` 中只读刷新状态。它不减少 `invulnerability_left`，也不推进战斗计时。暂停时生命组件停止物理更新，HUD 继续显示当前状态；短暂的文字反馈也暂停计时。
5. `hp == 0` 优先显示“已倒下 · R 重新开局”，不被受伤动画遮住。生命低于或等于最大值三分之一时，除了条色，还出现“生命偏低”文字。

同一组件重开时由 `reset_health()` 发信号同步数值；从倒下恢复会清除死亡状态。如果以后替换了生命组件，再调用 `bind_health(new_health)` 即可。它会先断开旧连接、清空比较基线，再绑定新组件，避免旧玩家的信号改到新面板。

## 三、在检查器中怎么调

打开 `run_hud.tscn`，选择 `Overlay/PlayerPanel` 可调整位置和大小。当前位于逻辑画布左上 `(40,12)` 到 `(300,106)`，上方安全区之外的战斗边界仍由原场景负责。`run_arena.gd` 中原有进度和控制从横坐标320开始，改宽面板时要一起复查它们。

选择场景根节点 `RunHUD`，调整导出的 `Health Feedback Seconds` 可改变受伤/治疗文字保持时长，默认0.7秒。这只影响展示，不改变受伤无敌时间。

选择 `HealthBar`，展开 Theme Overrides 的 Styles：`HealthTrack` 是背景，`HealthFill` 是填充；`HealthPanelStyle` 控制面板底色、圆角与边距。字号在各 Label 的 Theme Overrides 中修改。共享同一个样式资源会影响所有引用它的控件，想单独改某份先在编辑器中使资源唯一。

不要把进度条的 `max_value` 当作玩法参数。真实生命上限来自 `DemoBuild.max_health()`；运行时 UI 会覆盖场景中的初始显示值。伤害免疫时长在 `DemoHealth.invulnerability`，并非 HUD 脚本的反馈时长。

## 四、鼠标为什么能穿过血条

生命面板和其所有子 Control 都使用 `Mouse Filter = Ignore`。只改外层面板还不够，里面的 Label、ProgressBar 或容器如果接收输入，仍会挡住空白拖拽。测试会递归检查所有被动控件。

奖励卡、暂停、重开、静音和音量滑条是真实交互控件，需要接收鼠标。不要为了让血条穿透而把整个 HUD 的所有控件都改成 Ignore。当前奖励打开时发射器被阻止，关卡状态机决定何时恢复战斗；生命条本身没有暂停或恢复权限。

## 五、验证与最短试玩

本地自动检查用实际 Godot 路径执行：

```powershell
& '<本机实际Godot路径>' --headless --path . --script tests/roguelite_hud.gd
```

Windows 图形版 exe 可能提前向 shell 返回。需要确认真实退出码时，用 `Start-Process -Wait -PassThru` 并读取 `ExitCode`，同时核对日志的 `HUD CHECKS PASSED` 和无脚本错误。测试覆盖受伤、治疗、最大生命增长、低血文字、无敌结束、死亡、重开、换源、暂停和三/四卡共存。它不会证明玩家已经觉得界面好看。

手动最短步骤：

1. 打开 run 场景 F6，确认左上 `5 / 5` 与满条；在血条区域按住向后拖并松开，也应能发射。
2. 留在危险攻击范围内，等空心预警结束后承受一次攻击，观察数字和条同时减少，以及“受伤 / 无敌保护”出现后消失。普通身体碰撞不会扣血，不能用它测试受伤。
3. 生命不足时击杀到奖励门槛，若出现“饱餐”选择它，观察生命和条立即恢复。抽卡有随机性，不保证每次都出现；验证任意特定升级可用下面的开发调试办法。
4. Esc → 重新开局；确认生命上限回到5、满条，旧奖励/死亡状态不残留。也要测试生命归零后按 R 重开。
5. 把窗口改为1024×576，再看生命条、中文、三/四张卡；观察是否截断、与控制重叠、缩放后拖拽方向是否仍一致。

开发者需要稳定复现回血/上限时，可在临时测试脚本中使用真实 `DemoHealth`：先 `hurt(2)`，再把 `hp` 加到不超过 `max_hp` 并发 `changed.emit(hp)`；上限测试先增加 `max_hp`，同步合法 `hp` 后发同一信号。正式整局的治疗和上限增长由 `RunDirector.apply_build()` 处理，沿用 [教程010](010-kill-rewards.md) 的奖励规则。不要为测试给正式玩家界面添加免费治疗按钮，也不要把主动指定状态的夹具记成真实通关。

本轮用忽略目录中的独立HUD夹具进行1280×720和1024×576的真实渲染，查看生命3/5、受伤提示与四张卡：均完整显示。夹具只证明这组布局的渲染结果；实际战斗遮挡、按钮交互与视觉品质仍需 run 入口试玩和用户反馈。

## 六、常见错误与扩展

- 只连 `changed(hp)` 不刷新上限：强身后条的比例错误。每次都一起读取 `max_hp`。
- 只在伤害信号里显示无敌文字：无敌结束后标签卡住。只读刷新免疫状态，不让HUD修改计时。
- 给 `HealthBar.value` 加2当作治疗：只改画面，下一帧又回去。治疗应进入生命组件，由信号推到界面。
- 换组件时再 connect 一次却不 disconnect：旧源还会更新新玩家显示。统一走 `bind_health()`。
- 用头像装饰替代真实碰撞形状：表现和物理职责混在一起。未来头像、护盾、延迟扣血条应消费生命事件，不能改刚体形状、冲量或位置。

下一步如增加护盾，应先在负责战斗规则的组件定义护盾/生命消耗顺序，再增加独立显示字段与测试；如全面改主题，先按计划007展示完整样板，继续保持被动显示穿透与真实按钮独占输入。
