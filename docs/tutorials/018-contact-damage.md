# 018：橙色方块推得动却撞不破的漏伤

用户截图确认对象是普通橙色方块，不是伙伴或白饭。它只有1点生命，不能因为被撞飞就免伤。本次先写真实接触回归，改变节点加入物理世界的先后顺序，四个方向、0.5/4/20/100像素接触间隙；旧版32组里16组敌人仍1血，只有位移没有战斗事件。

## 根因与修复

`scripts/roguelite/combat_body.gd`通过上一份速度和接触法线计算迎面接近速度。但是两个刚体的`_integrate_forces`有先后顺序；若敌人先回调，`incoming_velocity`已换成撞飞后的速度，主球再读就可能把对方当成正在高速远离，算出0伤害速度。轻敌质量下调后更容易暴露该错误，表现与节点顺序相关。

现在每个刚体保留`incoming_velocity`与`_previous_velocity`两份快照以及`_velocity_frame`。读另一个刚体时调用`velocity_for_contact(当前物理帧)`：它本帧已经更新，就回读前一份；还没更新就读当前保存值。两者都取相同时间层次的速度，不把撞飞后的结果当作撞击前提。

这只修正接触取样，不把低速蹭碰改成伤害，不绕过主动发射链、配对去重或延后事件的版本检查。复位仍由物理状态接口执行，并把两份快照清零。首领/墙/同伴沿用各自既有碰撞与收益规则。

## 验证与扩展

`tests/roguelite_damage_contacts.gd`验证32组真实正面碰撞均能击破普通敌人，另检查两种节点顺序下低速主动碰撞和没有主动发射链的高速被动碰撞均不错误扣血。它使用真实Godot物理，而非直接调用`hurt(1)`冒充撞击。

本机使用固定Godot4.7.1运行该测试。正式整体检查入口仍为`tools/verify.ps1`。完整真人玩法仍需F6重新运行run场景，直撞剩余1生命普通敌人，确认击破、击杀/钱币只结算一次，清光残敌能推进；不要在已运行的旧窗口中只按R就当成加载新脚本。

不建议靠调低伤害门槛、反复增加发射冲量或让玩家穿过敌人来遮住漏伤。以后新增会更新接触速度的刚体，都应沿用同一帧快照读取规则，补不同处理顺序的真实接触测试。
