## 可以想成什么样的游戏

一个“打一下就会忍不住再试一次”的碰撞游乐场。玩家学的不是复杂按键，而是球和世界相撞时的规律：金属清脆、橡胶弹跳、泥地闷住，机关让同一杆产生意想不到但可理解的结果。

先走单人解谜的稳妥路线；以后可选挑战杆数、速通或创意沙盒。关卡像一段短小的物理笑话：起初觉得不可能，试几次发现“原来可以这样”。

## 建议的大致顺序（按效果推进，不先承诺日期）

| 阶段 | 做到什么 | 暂定产物 | 进入下一阶段的信号 |
| --- | --- | --- | --- |
| A 碰一下就舒服 | 力度、停稳、反弹、反馈都让人看得懂 | 物理参数对照实验 | 三人都能说清哪套手感更好 |
| B 让设计关卡变容易 | 目标/机关可视化编辑，数据和表现拆开 | 可复制的关卡积木 | 另一位开发者能独立拼出一关 |
| C 做一个小而完整的体验 | 3～5 个教学与组合关、切关、重试 | 10 分钟左右的内测版本 | 新玩家不用口头解释也会玩 |
| D 给碰撞一种性格 | 统一美术、材质声音、光与粒子语言 | 一关有代表性的完整表现 | 看一眼、听一下就知道碰到了什么 |
| E 让别人舒服地玩 | 设置、输入适配、可读性、性能与 PC 导出 | 可发给朋友的试玩包 | 换一台电脑能顺利打开和游玩 |
| F 再决定要长成什么 | 更多关卡/挑战/沙盒中只选一个重点 | 下一轮范围决定 | 玩家反馈支持继续投入 |

对三个人的分工建议：程序 A 侧重球和碰撞、程序 B 侧重关卡与工具，第三位负责关卡想法、视觉/声音方向与新手试玩；每隔一两项任务轮换讲解，避免只有一个人懂某模块。

## 第一批可转成 Issue 的草案

优先级是讨论顺序。每项真正启动时，都应带上测试、教程、目录与 Review；以下不重复工程清单。

| 编号 / 建议标题 | 优先级 / 依赖 | 交付与验收设想 |
| --- | --- | --- |
| D01 建立三套碰撞手感预设 | 先做 / 无 | 轻快、厚重、弹跳三套参数可切换；固定角度/力度比较，三人各记录感受；解释反弹/阻尼区别 |
| D02 让目标与机关在编辑器里可见 | 先做 / 无 | Goal 独立场景，移动节点时图形和传感器一起移动；机关大小变化能预览；另一人不用改代码即可摆一关 |
| D03 写清机关叠加和退出规则 | 先做 / D01 | 明确加速+粘滞、反重力+重置、重叠区域的优先级；先定规则再编码；进入/离开顺序都不残留错误状态 |
| D04 为拖拽瞄准做易读性实验 | 较早 / D01 | 比较球后拉线、发射箭头、力度分段；小窗口仍能看清；预测轨迹明确说明哪些效果不预测 |
| D05 做三关“只教一件事”的教学 | 较早 / D02 | 第 1 关只击球，第 2 关教反弹，第 3 关教一个机关；陌生玩家无需旁边解释即可完成 |
| D06 关卡切换与统一重试 | 较早 / D05 | 胜利后可下一关，随时重试；切换后杆数、机关状态、音效节点不串关 |
| D07 让不同材质说不同的话 | 中期 / D01 | 金属/橡胶/黏土各一套声音和粒子；同材质强撞比轻撞更明显，静止时不反复响 |
| D08 球的冲击形变与光效实验 | 中期 / D07 | 只缩放外观、不改变物理形状；闪光、余辉、轻震动可调；关闭震动后物理完全一致 |
| D09 建一个五分钟碰撞小工厂 | 中期 / D03、D06 | 选 2～3 个机关组合成 5 关，最后一关用已学规律解决；不临时引入新规则刁难玩家 |
| D10 提供基本 PC 设置与可访问选项 | 发行前 / D06 | 主音量、震动、全屏、清楚的重试提示；不只靠颜色区分机关；重启后设置保存 |
| D11 制作可交付的 Windows 试玩包 | 发行前 / D09、D10 | 固定 export templates 与版本号；在另一台电脑不装 Godot 也能运行；附一页操作说明 |
| D12 建立一次新玩家试玩记录 | 发行前 / D11 | 记录卡住位置、误操作、重试意愿；区分 bug/不理解/不喜欢，只挑最影响体验的前三项改进 |

## 可以放飞的玩法池

- **共鸣球房**：每次碰撞点亮一盏灯并敲出一个音，正确线路像演奏一段旋律。先试一关，判断声音是否真的帮助理解。
- **重力折纸**：进入不同区域后墙变成地板；未来若做 90 度重力旋转，要先验证视觉参照和眩晕感，当前原型只有上下反转。
- **黏住再放手**：球暂时粘在表面，借下一次发射重新选择路线；需要提前设计粘滞与当前阻尼机关的区别。
- **幽灵上一杆**：保留上一杆的淡淡轨迹，让失败也产生信息。若做回放，先研究物理可重现性，避免直接承诺精确重演。
- **会害羞的机关**：被撞一次才展开，迫使玩家先布置世界再进球；变化必须有清楚预告。
- **双球搭档**：先用重球推动机关，再让轻球通过。范围明显扩大，等单球稳定后再决定。
- **碰撞快照**：漂亮的一杆结束后生成静态轨迹纪念图，可作为关卡分享；先不做账号或联网分享系统。
- **每日“同一张桌”挑战**：每个人用相同起点挑战更少杆数；早期可线下比较，不急着上排行榜服务。

## 怎么把草案变成真正的 Issue

团队先选一项并收窄目标，再按下面格式复制到 GitHub；创建线上 Issue 前先得到用户授权。暂不批量创建，避免把脑洞变成欠债清单。

```text
标题：D02 让目标与机关在编辑器里可见
动机：设计关卡时不想一边改坐标一边猜位置。
范围：独立 Goal 场景 + 机关编辑器预览。
验收：移动/缩放后外观与检测区域一致；另一位开发者能复制并摆放。
不做：关卡编辑器、存档、联网。
依赖：无；请先确认现有碰撞层。
验证：自动检查 + 编辑器手动移动/复制 + F5 目标判定。
教学：如何摆一个目标、如何调整区域大小。
负责人：认领时填写。
```

建议首轮只认领 D01 和 D02；试玩后再决定 D03～D06，不同时把所有想法塞进开发队列。
