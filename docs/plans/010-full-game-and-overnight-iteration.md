### 2.2 Buff 文案映射

资源 ID 保持不变，便于测试、调参预设及存档式数据兼容。文案调整和数值调优分开记录。

| ID | 提议显示名 | 必须表达的效果 |
| --- | --- | --- |

| cooldown | 快速上弦 | 每级冷却 -0.25 秒，最多 4 级；显示实际冷却和本次收益 |
| double_launch | 双发 | 储存两次发射，逐次消耗、恢复；并非永久零冷却 |
| heavy | ！？肥肥？！ | 主球有效撞击伤害每级 +1，最多 3 级 |
| echo | 补刀 | 有效命中后 0.12 秒追加 1 点，不递归 |
| bowling | 保龄球 | 存活敌人在 0.6 秒内可命中另外两个不同敌人，不继续传代 |

| relay | 接力 | 增强伙伴互传冲量；保留未选天赋时已有的基础传能 |
| shrink | 小小的也很可爱 | 普通敌人和首领攻击范围每级缩小 15%，最多 2 级；不缩碰撞体 |
| pulse | 退！退！退！ | 每 4 战斗秒震退半径 150 内敌人，不直接造成伤害或授予免疫 |
| heal | 饱餐 | 立即恢复 2 点，不能超过上限 |
| choices | 运筹 | 后续成长四选一 |

文档标题明确“效果除外包外不改”。代码核对还发现：`explosion` 当前只由 `DemoCompanion` 触发，文档“非主球我方攻击体”可能包含保龄球敌人。首先列出这项语义差异；改名批次保留当前触发范围，运行文案写清“外包伙伴”，不借改文案扩大玩法。若随后采用更宽的触发范围，作为单独规则变更和测试项。

接力的括号提问可由代码回答：已有基础传能，选天赋后增加额外有上限的冲量，并不是没有天赋时完全不能接力。

外包涉及三处真实行为修改：`companion_count()` 从 1+等级改为等级；管理器允许 0 个；重开恢复 0 个。跟随/炸鱼在没有伙伴时不进入普通候选，接力至少 2 个才出现，防止前期抽到暂时无效的组合。保留首轮可选外包的保障，配合统计检查它是否变成唯一必选。

## 3. 方案选择与工作顺序

有三条可行路线：只补功能最快形成可玩版，但不会解决表现；一开始重做美术容易在地图改动后返工；推荐先完成可玩闭环，再依次做数值、表现两种对照。每轮只改变一类因素，才能判断改善来自规则还是反馈。

依赖顺序：

```text
核验基线 → 文案/零伙伴开局 → 机关组件 → 四图与整局接线
                                      ↓
                        功能验收 → 自动评估与有限调参
                                      ↓
                         实际画面对照 → 美术/动画/音效迭代
                                      ↓
                           回归/审查 → 本地可玩交付
```

建议搜索边界属于待评估假设：发射冲量以现值 1050 的 ±20% 为限，阻尼/摩擦先只在基线附近变化；反向动量抵消比较 0、0.3、0.6；敌人质量倍率 0.8–1.0；预警不短于 0.7 秒。冷却先比较 2.2/2.0/1.8 秒的独立候选，若改变基础冷却，须联动检查四级上弦每级均有实际收益，不能被旧下限夹成无效升级。所有这些是规则/数值变更，不能混入美术提交。

锁定项目：物理求解器、碰撞层、伤害去重、升级递归限制、出生安全、准确生命数字、暂停状态机。文案批次的 Buff 百分比和伤害效果也不参与盲搜；确需改动时先形成明确差异。

## 4. 如何评价爽感与保留改进

“爽感”本身最终由玩家体验判断。自动系统衡量的是与它相关的证据，不输出“玩家必然觉得好玩”的结论。数值评分和美术评分分开存，不用两者加总掩盖功能失败。

| 数值维度 | 权重 | 记录证据 |
| --- | --- | --- |
| 操作可控 | 25 | 冷却可用却无法改变方向的时段、反向纠偏用时、输入接受率、墙角滞留 |
| 撞击有效 | 25 | 速度合格接触的真实掉血率、单发击退/伤害、拒伤原因、接力长度分布 |
| 成长可感 | 20 | 同种子同输入在无升级/早期/成型构筑下的输出与操作差异；伙伴依赖卡是否有效 |
| 难度公平 | 20 | 出生/预警安全、尖刺伤害占比、首次受伤时刻、各策略存活/死亡分布 |
| 节奏 | 10 | 首次击杀/首次领奖时间、单位战斗时间的有效事件、清波后的空等、完整局时长 |

在基线测量完成后，将各项映射区间写入固定评估资源，再启动候选搜索。门槛和权重在搜索中不随结果改；若基准本身有问题，新版本评估规则必须让所有旧候选重跑，不能只重算新候选。

预备目标是改进方向而非保证值：首个有效击杀不拖过 10–15 秒；首次成长尽量在 30–45 秒内；普通有效接触拒伤率在排除明确冷却/无攻击资格后保持低位；训练外场景不出现明显生存/控制退化。实测显示与地图目标冲突时记录原因，不能靠降低门槛给自己判通过。

硬性否决项优先于分数：错误伤害、隐形碰撞、永动增能、自动无限连锁、出生即受伤、墙角/传送软锁、奖励失效、输入穿透、帧率明显退化。出现任一项，本候选不能替代已通过版本。

每轮保留：完整参数差异、训练/留出种子、策略、原始事件 JSON、均值/中位数及坏案例、录像或截图。选择在控制、成长、公平性上均有改善的候选；如果只提高击杀率却导致失控或一条构筑独占，保留为对照而非默认值。至少连续两轮没有改善时结束这组搜索，转向实际失败原因。

## 5. 一晚怎样安排，以及没做完怎样接续

以开始后的相对时间安排约 8–10 小时工作量；这是优先级预算，不是“一晚保证所有复杂机制和美术完美”的承诺。

| 时段 | 优先任务 | 阶段交付 |
| --- | --- | --- |
| 前 0.5 小时 | A，基线和需求核对 | 可恢复基线、验收清单 |
| 随后 0.5–1 小时 | B，文案和外包 | 0 伙伴开局、真实奖励前提 |
| 随后 2–3 小时 | C，机关组件和传送 | 单项机制回归与真实碰撞演示 |
| 随后 1.5–2 小时 | D，四图/整局 | 可从菜单打到首领并重开；通过 G1 |
| 剩余约 1–1.5 小时 | E，先测评估器再有限调参 | 基线与有限候选，留出场景证据 |
| 剩余约 1 小时 | F，最大体验短板的表现对照 | 一组实际运行美术/反馈改善 |
| 最后至少 0.5 小时 | G，收尾 | 验证、审查准备、可玩包和结果 |

时间不够时首先减少搜索候选和视觉变体，不砍功能回归和收尾。G1 未通过就继续修地图/整局，调参与大范围美术顺延；已经通过的稳定版本始终保留。任务困难不能用“只跑了几个小时”代替工作完成，但也不能用熬时间代替质量。

第一晚之后的接续顺序：完成遗漏功能/坏案例 → 扩大训练外的数值验证与构筑多样性 → 主球/伙伴/敌人/首领整套视觉资产 → 逐张卡面 → 同类型地图变体与分阶段随机 → 如确有操作需求再设计主动技能。每个包都沿用功能门槛、候选保留、实际证据和独立审查。

## 6. 连续运行的检查点与停止条件

每个小批次约 30–60 分钟记录一次“已完成任务、下一任务、修改文件、真实命令/结果、候选参数、最好版本、失败原因”。复用此计划的复选框与一份 `.local/overnight/checkpoint.json`，不再建立重复的大型 Agent 日志。用户插入反馈时先保存检查点，再按新反馈调整。

继续条件：有明确未完成任务或可验证的失败案例；有剩余评估/生成预算；没有外部权限依赖。结束条件：达到本轮认可的完成范围，或同组连续两轮无改善后转向下一个任务。出现必需的真人判断、新付费/外部生成条件、工具权限拒绝或无法验证的设计冲突时，保存可玩稳定版和具体问题，不绕过限制、不用虚构分数宣称完成。

本计划不自动创建定时任务，也不声称回复结束后仍在后台运行。整夜执行必须由实际保持运行的任务承载；启动时核对工作区与可用工具，并明确本次持续范围。没有开启的任务不能写成“今晚会自动做完”。
