# UI与肥鱼美术专项优化计划

日期：2026-10-31。目标：把当前调试场的观感改成有清晰层级、统一主题和战斗可读性的游戏界面。用户明确认为现有UI/主题不合格，本计划未实现、未验收。

依赖：[计划006](006-feedback-and-run-rhythm.md)先处理音效和生命面板；视觉方案与阶段/商店/事件布局一起考虑。此计划不自动扩展维维美/呆猫，不下载或拆包角色素材。

## 1. 方向与样板

推荐以“肥鱼拆迁队”为统一方向：圆润肥鱼和小鱼、浅暖色面板、深色低对比战斗地面；主球/伙伴用蓝青，敌人与危险用暖红，奖励与交互用金色。颜色之外同时用轮廓、图标和动态区分阵营，避免预警只靠颜色。

保留自制几何/矢量能力，先做一个完整战斗画面与一套奖励/商店面板样板，给用户看过再批量替换。不要先采购整包美术或给每种敌人堆复杂动画。备选为高对比霓虹街机风；目前推荐暖色圆润方向，与肥鱼题材及休息区更一致，最终风格由用户确认。

## 2. 文件结构与交付顺序

| 次序 | 交付 | 文件边界 |
| --- | --- | --- |
| 1 | 色板、字号、间距、圆角、按钮状态与图标规范 | 新 `resources/roguelite/ui/game_theme.tres`，补 `docs/art/ui_style_guide.md` |
| 2 | 战斗HUD：生命/储能/阶段/奖励进度，调试信息退后 | `run_hud.tscn/.gd`、`run_arena.gd`，需要时拆 `player_panel.tscn` |
| 3 | 可读的3/4选一卡片、暂停、商店、事件、结算 | `run_hud`、006新面板场景；统一Theme，不各写一套颜色 |
| 4 | 肥鱼/小鱼、三敌人、首领、白饭与障碍剪影 | `player_ball.gd`、`companion_ball.gd`、`enemy.gd`、`boss.gd`、`rice_lure.gd`、`theme_definition.gd`及主题资源 |
| 5 | 统一受击、死亡、选卡、转场反馈 | 表现脚本与信号；不修改伤害和物理碰撞形状 |

新增图标/绘图资源放项目内可编辑目录，记录用途与制作来源。若之后需要AI位图，先确认角色参考和用途，通过图像工具制作；不把临时生成图直接当已验收正式角色。

## 3. 具体检查清单

- [ ] 整理一张战斗HUD样板和奖励/商店样板，标注1280×720下布局，向用户展示后再全面实施。
- [ ] 生命条最醒目；发射储能可分1/2格，冷却数字可读；奖励进度与阶段目标有独立位置，不挤成长日志。
- [ ] 卡片突出标题/收益/当前等级与上限；长中文说明换行，四张时不截断。按钮有悬停、按下、禁用和键盘焦点样式。
- [ ] 暂停/商店/事件/结算明确说明当前状态、可行动作和继续按钮；战斗中不持续摆放长教程占场。
- [ ] 主球方向/体积易辨；小弟有伙伴特征；敌人预警、危险弹、白饭吸引圈与纯装饰可区分。
- [ ] 减少无意义网格、强亮边框与同时闪烁，碰撞反馈短促且对应真实事件；限制粒子/震动，保留关闭选项。
- [ ] 验证界面不拦截空白拖动，按钮松手取消仍可靠；屏幕缩放不改变发射方向/力度，暂停恢复不幽灵发射。
- [ ] 在1280×720及较小窗口检查中文字体回退、文字/面板对比度、3/4卡片和血量变化；另一台电脑重新调查环境后核验。
- [ ] 重用现有物理签名/主题隔离测试：换外观不能改变质量、形状、碰撞层、重力、主球冲量与同伴状态。新增必要的HUD行为回归，视觉品质由实际画面对照和用户评价验收。

## 4. 不属于本轮完成范围

本轮只保存计划。音效、可视血条、商店/事件、主题改版均不能写成已经实现。完整UI/美术交付时需更新教程、文件用途/目录和STATUS，并按Git阶段要求重新Review。不要用“所有测试通过”抵消用户对声音和观感的负面评价。
